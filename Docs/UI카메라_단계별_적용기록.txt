1-B 이후 시각 피드백: 게임 화면의 자글거림
- 사용자 확인: UI가 아닌 배경, 캐릭터, 문에서 보인다.
- Canvas Pixel Perfect는 HUD용 옵션이다. 월드는 PixelArtUpscaleRig의 별도 저해상도 RT와 PixelArtSharpUpscale 셰이더로 그리므로 월드 보정과 구분한다.
- 현재 CameraSettings는 OrthographicSize 6, PPU 32. 기본 줌에서 표시되는 세로 월드 픽셀은 384이며, FHD 출력일 경우 확대 배율은 1080 / 384 = 2.8125이다. 실제 테스트 출력 해상도는 확인하지 않았다.
- 월드 카메라의 위치는 이미 원본 도트 격자로 정렬하지만, 최종 출력은 소수점 UV 보정과 sharp bilinear 경계 보간을 사용한다. 이는 부드러운 이동을 위한 처리이며 자글거림의 원인 후보이다. 원인 확정은 아니다.
- 문 스프라이트는 Point 필터와 mipmap 꺼짐을 확인했다. 전체 스프라이트 설정을 일괄 변경하지 않는다.
- 대응 후보: HUD Pixel Perfect는 끈 채 유지하고, 월드의 최종 출력 위치를 화면 픽셀 단위로 정렬하는 비교를 우선 고려한다. 엄격한 정수 배율은 더 강한 대안이나, 줌/여백 또는 이동 느낌에 영향이 있어 별도 비교가 필요하다.
- 이번 분석에서는 게임 코드와 씬 설정을 추가로 변경하지 않았고, 테스트를 실행하지 않았다.

1-C단계: 최종 월드 출력 위치만 화면 1픽셀 간격에 정렬

- 변경 파일: Assets/Scripts/Managers/Camera/PixelArtUpscaleRig.cs.
- 카메라의 실제 위치나 줌 대신, 월드 이미지를 최종 화면에 표시할 때 쓰는 UV 오프셋만 변경했다.
- 카메라 출력 폭/높이와 현재 시야 크기로 화면 1픽셀의 월드 길이를 구한다. 표시 영역의 절대 월드 좌표를 그 간격에 반올림한 뒤, 저해상도 RT 내부의 오프셋으로 변환한다.
- RT 내부 오프셋부터 반올림하지 않는다. RT가 한 도트 이동할 때 비정수 확대 배율 때문에 화면 정렬 기준이 달라지는 것을 피하기 위해서다.
- Main Camera의 위치, OrthographicSize, 종횡비, 표시 영역 크기, 저해상도 RT 크기, 업스케일 필터 및 후처리는 유지했다. 입력 좌표 변환과 충돌 판정도 바꾸지 않았다.
- HUD는 1-B단계의 Camera 모드 + Pixel Perfect 꺼짐 그대로다. 다른 캔버스와 남은 커밋은 건드리지 않았다.
- 화면 출력의 반올림 보정은 축마다 최대 반 화면 픽셀이다. 원본 도트 한 칸 단위로 움직이게 만드는 변경은 아니다.
- 비교 결과: 사용자가 렉 없음, 자글거림 지속을 보고했다. 최종 화면 위치 정렬만으로 현재 시각 문제를 해결하지 못했다.
- 복구 자료 폴더에 PixelArtUpscaleRig.before-step1c.cs와 step1c-before.json을 저장했다.
- Unity 실행, 플레이 테스트, 빌드는 하지 않았다. 코드 변경 범위와 나머지 자산 유지 여부만 정적으로 확인했다.

1-C 이후 대응 제안 (미적용)
- HUD Canvas의 Pixel Perfect와 월드 카메라의 픽셀 정렬은 별개다. 이번 결과로 월드용 픽셀 퍼펙트도 동일한 렉을 유발한다고 결론 내리지 않는다.
- 먼저 실제 출력 해상도와 Game View 표시 배율을 고정하여 비교한다. 에디터가 게임 화면을 다시 축소해서 표시하는 경우도 구분한다.
- 확대 보간 문제를 가르는 강한 비교는 월드만 정수 배율로 표시하는 것이다. FHD/PPU 32에서 3배 확대라면 OrthographicSize 5.625가 되므로 기존 6보다 시야가 좁아진다. 사용자 동의 없이 적용하지 않는다.
- 기존 시야를 유지하는 대안은 정수 배율 출력에 여백을 허용하거나, 현재 확대 필터의 경계 혼합을 더 부드럽게 만드는 것이다. 각각 화면 활용도 또는 도트 선명도에 손실이 있다.
- 정수 배율에서도 자글거림이 남으면 스프라이트 변형, 셰이더/후처리 등 다른 원인을 분리해야 한다. Pixel Perfect가 만능 해결책이라고 단정하지 않는다.
- 기존 PixelArtUpscaleRig 위에 다른 픽셀 퍼펙트 카메라를 무작정 추가하지 않는다. 동일한 줌/렌더 텍스처를 두 시스템이 제어하지 않도록 한 경로에서 비교한다.
- 이 제안 단계에서는 게임 파일을 추가로 바꾸지 않았다. 당시 남겨둔 1-C 코드는 이후 1-D에서 원복했다.
