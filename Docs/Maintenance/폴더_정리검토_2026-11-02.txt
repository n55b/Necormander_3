1. 조사 범위와 결론

Assets와 Docs에서 외부 패키지·구매 에셋·메타 파일을 제외한 1,279개 파일을 목록 기준으로 확인했다.
C# 315개(런타임 253, 에디터 62), 프리팹 176개, 자체 Resources 폴더 아래 파일 404개가 포함된다.
주요 폴더, 직렬화 GUID 참조, 문자열 로딩 경로, 에디터 생성 도구의 고정 경로를 함께 조사했다.
모든 파일의 동작을 실행 검증한 것은 아니다. Unity 플레이·빌드·게임 테스트는 진행하지 않았다.

정리할 부분은 있지만, 프로젝트 구조를 전부 바꿀 필요는 없다.
Scripts / Prefabs / Animations / SOData / Resources처럼 파일 종류로 나눈 큰 틀은 유지하고,
같은 기능의 하위 분류를 맞추며 잘못된 위치와 임시 이름부터 정리하는 편이 적절하다.
스크립트 클래스명 변경이나 시스템 재설계는 이번 폴더 정리와 분리한다.

3. 중복·잔재 후보: 별도 검증 후 결정

가. 정확히 같은 파일 내용
  Assets/Resources/Sprites/Effect/PointLight.aseprite
  Assets/Resources/Sprites/Spot_Light.aseprite
  파일 바이트는 같지만 GUID·스프라이트 ID는 다르다.
  PointLight는 SpotLight 프리팹에서 사용하고 Spot_Light는 검색한 직렬화 참조가 없었다.
  PointLight를 기준으로 통합할 후보이며, 문자열 로딩과 서브에셋 참조까지 확인 후 결정한다.

나. 확장자만 다른 동일 Resources 주소
  Sprites/UI/UI — PNG / aseprite
  Sprites/Effect/Move_Effect — PNG / aseprite
  Sprites/Effect/Dash_Effect — PNG / aseprite
  Sprites/Title_Image — PNG / aseprite
  같은 파일이라는 뜻은 아니다. 정지 이미지와 애니메이션 용도를 확인해 이름·위치를 구분할 후보.
  현재 기능 오류가 확인된 것은 아니지만 문자열 로딩 주소가 겹쳐 관리가 모호하다.

다. 오래된 씬 관련 파일
  Assets/Scenes/SpawnSystem, PortalSpawnSystem, DynamicSpawnSystem, Map 아래 NavMesh 자산 6개.
  대응 씬 파일이 없고 검색한 직렬화 참조가 없었다. 최종 의존성 확인 후 정리할 후보.
  Assets/Screenshots의 스크린샷 2개는 Docs/Screenshots 등 Assets 밖으로 옮길 후보.
  InputSystem_Actions.inputactions는 참조가 확인되지 않은 기본 입력 자산 후보.
  PlayerInputSystem.inputactions는 플레이어 프리팹·프로젝트 설정에서 사용 중이므로 유지.
  EliteTestScene은 현재 빌드에 포함되어 있으므로 Test라는 이름만으로 제거하지 않는다.

라. 삭제하면 안 되는 유사 이름
  Sprites/Minion/Old의 7개 스프라이트는 참조가 있다. Skeleton 계열 이름으로 바꾸는 편이 적절하다.
  다른 Sprites/Old 폴더의 8개는 별도 의존성 검토가 필요하다.
  서로 다른 Traps.aseprite, Chest.aseprite는 내용이 다른 자산이다.
  WatchTower와 WoodWall의 Wall_Wood_Right.prefab도 둘 다 사용 중이다.
  위 파일들은 이름 중복만으로 병합·삭제하지 않는다.

4. 실행 순서 제안

1) 추적된 임시 출력·캐시 정리, 문서·도구 분류, 고정 입력 경로 갱신.
2) Editor 통합과 역할에 맞지 않는 소수의 런타임 스크립트 이동.
3) Resources 상대 주소를 유지하면서 네 군데의 자체 Resources 통합.
4) 실제 사용 중인 Test / SpriteTests / 날짜 폴더를 역할 기반 이름으로 정리.
5) 이펙트·셰이더·자료 파일의 기능별 하위 분류 통일.
6) 참조가 불명확한 중복·옛 베이크 자산은 의존성 확인을 마친 것만 마지막에 정리.

이동 원칙:
  Unity 자산은 기존 .meta와 GUID를 유지해 이동한다.
  aseprite 원본은 재생성하지 않고 임포터 설정과 서브에셋 ID를 유지한다.
  Resources.Load, AssetDatabase 경로, 생성·검증 도구, 문서 링크를 이동 목록과 대조한다.
  스크립트·애니메이션 이름, 이벤트, 씬 이름, 메뉴 기능은 불필요하게 변경하지 않는다.
  외부 에셋·패키지·자동 생성 캐시·StreamingAssets의 역할은 유지한다.
  현재 조사에서는 고아 .meta나 중복 GUID가 발견되지 않았다.
  정리 실행 후에는 Missing Script/누락 GUID/문자열 로딩 경로/에디터 컴파일을 확인한다.
  플레이 테스트는 사용자가 진행한다.

이번 보고는 폴더 정리에 대한 제안이다. 후보 파일을 삭제해도 된다는 최종 판정은 아니다.
