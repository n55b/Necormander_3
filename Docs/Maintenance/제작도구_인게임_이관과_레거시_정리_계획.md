# 제작 도구 인게임 이관과 레거시 정리 계획

2026-11-26 조사 기준이다. 코드는 바꾸지 않았다. 조사 범위는 다음과 같다.

- `Assets/Scripts/World/Workshop` 전체
- `Tools/기획` 편집기 7종과 부속 메뉴, Sunyunie Panel
- `Assets/Editor` 104개 파일
- `Assets/Scripts` 374개 파일의 GUID·코드 참조
- 씬·프리팹·SO·문서

레거시 후보는 후보마다 반박 검증을 거쳤다. 계획 초안은 사실·파손 위험·사용성·순서 네 관점으로 다시 검토해 고쳤다.

**요약**

- 제작실의 범용 **콘텐츠 수치** 화면은 이미 SOData 78개와 Resources 설정 9개의 수치를 저장한다. 그래서 이관은 새로 만드는 일이 아니다. 범용 편집기의 빈칸을 채우고, 그 위에 도메인 화면을 얇게 얹는 일이다.
- 빈칸은 일곱 가지다.
  1. 그림·소리·프리팹 참조
  2. SO 목록(레지스트리) 편집
  3. 목록 원소 추가·삭제·순서
  4. Color·Vector
  5. 한글 라벨·위젯
  6. 미리보기·시험 연동
  7. 변형 이름 변경·삭제
- **원리: 맵 편집과 같다(2026-11-26 결정).**
  - 원본 에셋은 바탕으로 두고, 수정은 DATA 덮어쓰기, 새로 만들기는 DATA의 새 ID, 삭제는 DATA의 삭제 표시로 처리한다. 이름은 표시 이름이라 언제든 바꾸고, 세이브가 쓰는 내부 ID는 바뀌지 않는다.
  - 그래서 생성·수정·이름 변경·삭제·복원을 모두 게임 안에서 한다.
  - Unity에 남는 것은 새 C# 타입(새 효과·패시브·AI 행동), 새 그림·프리팹·애니메이터 제작, 임포트·배선 도구, 삭제 표시된 원본 파일의 정리(선택)뿐이다.
  - 기존 그림·프리팹·소리는 게임 안에서 고른다.
- **순서**: P0 선행 정리 → P1 공용 기반과 상태이상 → P2 아이템 → P3 몬스터 → P4 소환수 → P5 장비 → P6 화면·연출·사운드. 레거시 L1~L3은 별도 B 트랙으로 사이사이에 처리한다. 도메인 하나가 끝나면 그 Unity 도구를 루트 `Legacy`로 보낸다.
- **레거시**: 반박 검증을 통과한 보관 대상은 에셋 15건, 문서·외부 도구 11건, 에디터 도구 7건, 런타임 정리 12건이다. L5(시스템 은퇴)는 2026-11-26에 결정했다.
  - 우클릭 데이터 시스템과 물리 확산 맵 생성 경로는 보관한다. 소환수 스킬(현재 우클릭)에는 영향을 주지 않는다.
  - 궁수 엘리트와 `MapDesign.unity`는 남긴다.
  - AI 차단은 `.rgignore`에 팀 공유 `.claude/settings.json`의 읽기 거부 규칙을 더해 강제한다.

# A부. 제작 도구 인게임 이관

## 1. 현재 제작실이 동작하는 방식

| 구성 | 현재 동작 | 이관에서 쓰는 방법 |
|---|---|---|
| 화면 | `RoomWorkshopWindow`(partial 16개)가 조작할 때마다 `Draw(Page)`로 640×360 논리 좌표의 uGUI를 처음부터 다시 만든다. 이 컴포넌트는 LevelWorkshop 씬에 있어 시험에 들어가면 파괴된다. | 새 페이지는 partial 파일 하나씩 둔다. 목록-상세 골격, 위젯, 화면 상태 보존은 공용으로 만든다(4.7, 5장). |
| 저장 | `ProjectContentStore`가 DATA 문서(폴더) 단위로 잠금·저널·3자 병합·원자적 교체를 처리한다. **DATA 저장은 체크아웃에 연결된 기본 작업 공간(Authoring)에서만 된다.** 개인 로컬 저장은 방·층·마을 전용 경로뿐이다. | 새 저장 형식을 만들지 않는다. 도메인 화면은 기존 `<group>/<에셋 GUID>/parameters.json` 문서를 큐레이션한다. 비연결 상태에서는 읽기 전용이다(9장 결정 기록). |
| 수치 적용 | `ProjectParameters`가 리플렉션으로 필드 경로를 만든다. 저장 직후 살아 있는 SO에 덮어쓰고, 플레이가 끝나면 되돌린다. 플레이 중 에셋 저장은 `ProjectContentAssetSaveFilter`가 막는다. 빌드에서는 씬마다 굽힌 `ProjectParameterBindings`가 적용한다. | 새 덮어쓰기 종류(목록 구조·멤버십·에셋 참조)는 모두 적용·복원·저장 차단·빌드 검증에 등록한다. 빠뜨리면 플레이 중 값이 `.asset`에 샌다. |
| 복제 | `ProjectContentVariants`가 `CATALOG/VARIANTS/<id>/definition.json`(template, title)으로 런타임 복사본 `content_<id>`를 만든다. 복사본은 원본이 속한 Growth·Shop 목록에 자동 가입한다. | 플레이어 빌드는 에셋을 만들 수 없다. 그래서 인게임의 새 콘텐츠는 모두 변형이다. 세이브 키 `content_<id>`는 고정이므로 표시 이름만 바꾼다. |
| 시험 | `WorkshopTrial`이 세이브·PlayerPrefs·난수·조명을 격리하고 BattleScene/VillageScene을 연다. 시작하려면 방 Draft가 있어야 하고, 복귀는 F6이다. | 시험 왕복 계약, 시험장, 로드아웃, 도구막대를 추가한다(5.4). |
| 검증 | `-Suite WorkshopPlayMode`·`ProjectContent`·`LevelWorkshop`·`UIResolution`·`Typography`. 검사기는 **버튼 GameObject 이름(=캡션)** 으로 클릭한다. 예: `콘텐츠 수치`, `maxStack   …`, `플레이어 수치`. | 버튼마다 고정 이름을 붙인다. 기존 캡션은 고정 이름으로 그대로 보존한다(4.7). |

범용 편집기가 지금 못 하는 것(`ProjectParameters.cs` 확인):

- Sprite·GameObject·AudioClip·AnimationClip 참조를 목록에서 조용히 뺀다(`:63-68`).
- SO 참조 목록(`GrowthRegistrySO.items` 등)은 통째로 건너뛴다(`:82`).
- 목록 원소는 이미 있는 것만 편집한다. 키는 public `id` 필드가 있으면 `@id`, 없으면 인덱스다(`:84-93`). 인덱스 키(`effects/0/...`)는 Unity에서 순서를 바꾸면 다른 원소에 붙는다.
- Color·Color32·Vector2·Vector3는 허용하려는 코드가 있지만 `IsSerializable` 조건 때문에 빠진다(`:96-100`, 잠재 버그). Vector2Int·Vector3Int는 필드가 private이라 조건을 고쳐도 빠진다.
- `itemName`·`minionName`·`equipmentName`·`id`·`key`·`*Id`를 이름으로 일괄 제외한다(`:56`).
- 라벨은 필드 경로 그대로다. enum은 영문 이름을, bool은 `True`를 타이핑한다. 한글 사전 `DesignerInspectorLabels`는 Editor 어셈블리에 있다.
- 실행 취소, 자동 복구 초안, 나갈 때 미저장 확인, 충돌 해결 화면은 방 편집에만 있다.
- `formerAssetNames`(세이브 옛 이름)와 `minionType`(고유 키 아님)이 **지금도** 편집 가능하게 노출돼 있다.

## 2. 이관 원칙

1. **맵 편집과 같은 원리다.** 맵은 원본 방 프리팹을 바탕으로 두고, 원본 방 수정은 `WORLD/ROOMS/<원본 GUID>`의 덮어쓰기로, 새 방은 새 ID 문서로, 던전 등록은 `WORLD/POOLS` 파일로 처리한다. 프리팹 파일 자체는 만들거나 지우지 않는다. 다른 콘텐츠도 같다.

   | 조작 | 처리 |
   |---|---|
   | 수정 | 원본·새 콘텐츠 모두 `<group>/<id>/` 문서의 덮어쓰기 |
   | 새로 만들기 | DATA 새 ID(변형). 기존 항목 복제 또는 빈 상태에서 시작 |
   | 이름 바꾸기 | 표시 이름을 바꾼다. 세이브가 쓰는 내부 ID(원본 에셋 이름, `content_<id>`)는 바뀌지 않아 세이브가 깨지지 않는다 |
   | 삭제 | 삭제 표시 문서(4.3). 게임의 모든 목록·풀·편집 목록에서 빠지고, "삭제됨" 필터에서 복원할 수 있다. 기존 세이브가 그 항목을 들고 있으면 해석은 유지해 갑자기 사라지지 않게 한다 |
   | 원본 파일 정리 | 선택 사항이다. Unity의 "삭제 표시된 원본 정리" 메뉴가 참조를 확인한 뒤 `.asset`을 `Legacy`로 옮긴다. 빌드된 게임은 에셋 파일을 지울 수 없기 때문이다 |

2. **게임 안에서 자유롭게 편집한다.** 등급 변경(일반 ↔ 엘리트), 목록 가입·탈퇴, 참조 교체, 목록 원소 추가·삭제를 게임 안에서 한다. 새 원본 에셋을 Unity에서 만든 경우를 위해 `RegistryMenuTools`는 빠진 아이템·장비를 레지스트리에 붙이는 기능을 더해 남긴다.
3. **같은 내용을 고치는 원본은 하나다.** 도메인을 화면에 여는 커밋에서 다음을 함께 처리한다.
   - 같은 에셋을 편집하는 Sunyunie 탭과 인스펙터를 읽기 전용으로 바꾸고 "제작실에서 편집" 표시를 붙인다.
   - 도메인 이관이 끝나면 옛 Unity 창은 `Legacy`로 보낸다.
4. **필드 하나에 화면 하나.**
   - 상태이상 수치는 상태이상 화면이 소유한다.
   - 이동·대쉬·스왑·자동 공격·기본 능력치는 플레이어 화면이 소유한다.
   - 다른 화면에는 읽기 전용 요약과 "열기" 링크만 둔다.
   - 찾기 결과는 항상 소유 화면으로 연다.
   - 범용 콘텐츠 수치 화면은 "모든 필드" 보기로 남긴다. 같은 초안 저장소를 쓰므로 충돌하지 않는다(4.6).
5. **반영 시점을 화면이 알려준다.**
   - 저장 후 상태 줄에 반영 시점을 쓴다. 예: "다음 습득부터", "다음 플레이어 생성부터", "다음 부여부터".
   - 즉시 반영이 필요한 곳은 저장 후 갱신 훅을 쓴다(4.5).
6. **Unity에 남는 것**:
   - 새 효과·패시브·AI 행동 C# 타입
   - 프리팹·애니메이터·클립·스프라이트 제작과 임포트(기존 것을 고르는 일은 게임 안)
   - 삭제 표시된 원본 파일 정리(선택), 레지스트리 배선, 카탈로그 굽기, 프리팹 배선 도구, 검증 스위트
   - AnimationCurve·Gradient·TileBase·LayerMask·Shader 필드. 예: `FeedbackCatalog.motion`, `AnimPhase.movementCurve`, `CameraSettings`의 셰이더
   - 편집 모드 저작에 쓰는 렌즈·PPU 값. 게임 안에서 바꾸면 Scene 뷰와 `-Suite ArtDirection` 기준이 실제 게임과 달라진다.

추가 이관 대상:

- **Sunyunie Panel 수치 탭 9개**: 화면·이동, 던전, 상태이상, 연출, UI 소리, 글자 모션, 분위기, GPU 입자, 피해 숫자. 패널에는 제작실 진입 버튼과 아트 탭만 남긴다. 단, 다음은 Unity 전용으로 남긴다.
  - 연출 탭의 "기존 연출"(`ExistingFeedbackCatalogEditor`). 프리팹·재질·씬의 실제 컴포넌트 값을 고치는 기능이다.
  - 화면·이동 탭의 렌즈·PPU.
- **화면·이동 탭의 플레이어 5값은 지금 원본이 둘이다.** DATA `BALANCE/PLAYER`가 플레이마다 프리팹 값을 덮어쓰므로, 패널에서 고친 "프리팹 기본값"은 반영되지 않는다. P0에서 프리팹 기본값 쪽만 읽기 전용으로 바꾼다. "현재 플레이어 · 시험값"은 인게임 F7 오버레이가 생길 때까지 유지한다.
- **F8 조명 패널**: 이미 게임 안 UI다. 하지만 던전 조명을 저장할 곳이 없고, 마을만 저장된다. 던전 조명은 `CameraSettings`(PRESENTATION/CAMERA) 하나에 저장하는 것으로 시작한다.
- **그룹이 없는 설정 SO**: `UI/CombatText`, `HitBoxColorConfig`, `StatusEffectPalette`, `UI/Chrome`. `ProjectParameterBindings.Group()`에 추가한다.
- **UI 스킨 설정 열기** → 화면·연출 화면의 UI 스타일로 옮긴다. 프리팹에 스킨을 붙이는 메뉴와 `OptionSceneSkinTool`은 Unity에 남긴다.
- **시험용 인스펙터 값**: `VillageDebugLoadout`, `debugStartFloor`. 시험 로드아웃 하나로 합친다(5.4).
- **Unity Localization 표 직접 편집**: DATA가 번역 전체를 덮어쓰므로 Unity에서 고쳐도 반영되지 않는다. 문서로 금지한다.

## 4. 공용 기반

괄호 안은 처음 필요한 단계다. 지금 이미 노출된 위험을 막는 항목은 P0에 둔다.

### 4.1 필드 종류와 키 — `ProjectParameters`

1. **편집 금지 표시 (P0)**: `ProjectParameters.cs:56`의 이름 하드코딩을 속성 또는 표 기반 제외로 바꾼다. 다음 필드는 읽기 전용으로 보인다.
   - `formerAssetNames`, `minionType`, 아처 보스의 실행 상태 필드, `animState_*`·`label_*`
   - 목록 키로 쓰는 필드
2. **목록 원소의 안정 id (P0)**: `ItemEffect`, `EquipmentPassive`, 대기 효과 항목, `UISoundSettings.windows`, `FeedbackCatalog.effects`·`existingEffects`에 `[HideInInspector] public string id`를 추가한다.
   - 키 조회가 public 필드만 보므로 private `[SerializeField]`로 만들면 동작하지 않는다.
   - `OnValidate`에서 비었거나 중복된 id를 다시 발급한다. Unity 목록의 `+`와 장비 편집기의 "복사"가 id까지 복제하기 때문이다.
   - 저장 검증과 `ValidatePublished`가 중복·빈 id를 거부한다.
   - `uiName`·`cue`처럼 편집 가능한 값은 키로 쓰지 않는다. 바꾸는 순간 자기 키가 사라진다.
   - `EnemyCount`·`FloorBossEntry`는 같은 숨김 id를 쓴다.
   - **비용이 0인 시점은 지금이다.** DATA에 `parameters.json`과 `CATALOG/VARIANTS`가 아직 하나도 없다. 착수 전에 팀 체크아웃과 활성 브랜치에도 없는지 사전 점검 스크립트로 확인한다(8장).
3. **Color·Vector (P6)**: Color·Color32·Vector2·Vector3는 `IsSerializable` 조건을 빼고 명시 허용한다. Vector2Int·Vector3Int는 x·y·z 프로퍼티로 읽고 쓰는 전용 분기를 둔다(경로 `field/x`). 대상 예: 글자 모션 `swatches`, 피해 숫자 `swatch`, GPU 입자 `decorativePixelBudget`.
4. **이름 허용 (P2)**: 세이브 키가 아닌 표시 이름만 연다.
   - 대상: `ItemSO.itemName`, `EquipmentSO.equipmentName`, `EnemyMinionDataSO.minionName`.
   - 허용 여부는 실제 타입으로 판정한다. `minionName`은 `MinionDataSO`에 선언돼 메인 소환수와 공유하므로, 선언 타입으로 판정하면 메인 소환수 이름까지 열린다.
   - 원본 문서에만 적용한다. 변형의 이름 원본은 `definition.json` title 하나다.
   - `Create`는 parameters를 복사할 때 이름 키를 뺀다.
   - 검증은 변형 parameters의 이름 키를 거부한다.
   - `TreasureSO.itemName`은 세이브 키라 계속 막는다.
5. **에셋 참조 카탈로그 (P2)**: 빌드 시 굽는 표 하나에 후보 에셋을 GUID(+스프라이트 이름)로 등록한다.
   - 후보: Resources 시트 스프라이트, 음원 85개, 손 `AnimatorOverrideController` 3개, 제작실 배치 프리팹.
   - 저장 형식: `"guid"` 또는 `"guid:이름"` 문자열.
   - 굽기는 `WorkshopBuild.Bake`, 검증은 `ProjectContentBuild.PrepareForBuild`에 붙인다.
6. **SO 참조 목록 = 멤버십 문서 (P2)**: 레지스트리 문서 아래 `MEMBERS/<목록 필드>/<항목 id>.json`(`{"included":true|false}`)을 둔다.
   - 항목마다 파일이 따로라 두 사람이 각자 등록해도 충돌하지 않는다.
   - `parameters.json`이 없어도 MEMBERS를 적용하도록 `Load`를 고친다.
   - MEMBERS의 대상 에셋은 `Published()`가 빌드 entries에 넣는다. 그래야 Windows 판에 포함된다.
   - 강화 트리처럼 짧고 순서가 있는 배열(`upgradeOptions`)은 id 배열 값 하나로 저장한다.
7. **목록 구조 문서 (P2)**: 원소의 추가·삭제·순서·종류를 `LISTS/<필드 경로>/<원소 id>.json`(`{"type","order","values"}` 또는 `{"removed":true}`)에 기록한다. 문서가 하나라도 있으면 적용 시 목록을 새로 만들고, 복원 때 원래 목록 참조를 되돌린다.

### 4.5 미리보기와 반영 (P1)

- **미리 적용**: 저장 전 초안을 살아 있는 SO에 적용하고, 취소하면 되돌린다. 기존 `originals` 복원 구조를 그대로 쓴다. 미저장 초안으로 시험할 때도 이 경로를 쓴다(5.4).
- **저장 후 갱신 훅**: SO 타입별 한두 줄짜리 정적 사전이다. 예: `ItemPouch.Refresh`, `UISoundSettings`·`FeedbackCatalog` 캐시 비우기, `CameraSettingsApplier.ApplyToAllLoadedScenes`, `UISkinSettings.NotifyChanged`.
- **편집 모드 검사용 `WithPublished(Action)`**: Published를 적용한 뒤 Restore한다. Unity에 남는 검사(`CriticalItemsCheck`, `CombatMovementCheck` 등)가 실제 게임 값을 검증하게 한다.

### 4.6 문서 안전장치

- **초안 저장소 (P1)**: 문서 경로를 키로 하는 `DraftStore` 하나를 둔다. 문서마다 basis, 초안, 실행 취소 스택을 가진다. 도메인 화면, "모든 필드", F7 오버레이가 모두 이것을 읽고 쓴다.
- **저장 범위 (P1)**:
  - Ctrl+S는 현재 항목을 저장한다.
  - 헤더의 "미저장 n"을 누르면 초안 목록과 [모두 저장](=Ctrl+Shift+S)이 나온다.
  - [변경 취소]는 현재 항목에만 적용하고, Ctrl+Z로 되돌릴 수 있다.
  - 미저장 확인은 화면 이동, 메뉴, 플레이 종료, 작업 공간 전환, 프로젝트 연결 때 띄운다.
- **"DATA가 덮어씀" 표시 (P1)**: `DesignerAssetInspector`가 해당 GUID의 `parameters.json`을 확인한다. 있으면 배너를 띄우고 덮인 필드를 읽기 전용으로 둔다.
- **판 차이 허용 (P1)**:
  - 실행 중에는 모르는 키를 경고 후 건너뛴다. 엄격한 검사는 빌드(`ValidatePublished`)에서만 한다.
  - 편집기의 `Published()`도 문서 하나가 잘못됐다고 세션 전체를 중단하지 않는다. 그 문서만 건너뛴다.
  - 제작판은 요청할 때만 빌드하므로 팀원마다 판이 다르다. 옛 판이 새 문서를 열면 "제작판을 갱신하세요"를 표시하고 그 문서 저장을 막는다.
- **여러 문서 묶음 저장 (P3)**: "이 적 전용으로 복제", "공유 스킬 분리"는 변형 생성과 참조 변경을 함께 한다. 하나의 저널에 기록하거나, 실패하면 새 변형을 되돌린다.
- **글리프 누락 경고 (P2)**: 입력한 이름·설명에 비트맵 아틀라스에 없는 글자가 있으면 입력칸 옆에 표시한다. 아틀라스 재생성은 Unity의 `Tools > UI > Rebuild Pixel Font Atlases`다.
- **충돌 해결 화면 일반화**: 팀 공용 배포 전까지 `parameters.json`에도 필드 단위 3자 비교 화면을 연다.

### 4.7 화면 구조 (P1, 맨 먼저)

- **페이지 등록표**: 페이지를 하나 더하면 지금은 `Draw` 분기, Ctrl+S, `SaveAllDocuments`, 연결 리셋 네 곳을 고친다. 이를 그리기·저장·변경 여부·초기화·단축키를 한 줄로 등록하는 표 하나로 모은다. 새 페이지는 자기 상태를 자기 partial 파일에 둔다.
- **고정 이름**: `WorkshopUI.Button`에 고정 이름 인자를 추가하고, 검증은 그 이름으로 클릭한다.
  - 기존 캡션(`플레이어 수치`, `콘텐츠 수치`, `대사 편집`, `UI·보상 번역`, `아트 원본`)은 고정 이름으로 보존한다.
  - 범용 화면의 행은 화면에 한글 라벨을 보여 준다. GameObject 이름은 지금처럼 `<코드 경로>   <값>`으로 유지한다.
- **`WorkshopSession`**: 정적 화면 상태로, 기존 `remembered*` 패턴을 확장한다. 현재 페이지, 선택 항목 id, 하위 탭, 목록 페이지·스크롤, 포커스 컨트롤을 담는다. 시험이나 게임 오버에서 돌아오면 이 상태를 복원한다. 복귀 분기 순서는 층 복귀 → 콘텐츠 화면 → 방 편집 → 작업대다.
- **갱신 규칙**: 값 위젯(스테퍼·슬라이더·토글·인라인 입력)은 자기 라벨, 강조, ↺, 목록 배지, 미리보기 문구만 그 자리에서 고친다. `Draw`는 구조가 바뀔 때만 부른다(항목 전환, 원소 추가·삭제, 탭 전환). 지금처럼 매번 다시 그리면 드래그 중인 슬라이더가 파괴되고 스크롤이 맨 위로 튄다. 상세 열은 ScrollRect로 만든다.

## 5. 편하게 쓰는 화면

### 5.1 진입: "게임 콘텐츠" 허브

작업대의 "게임 콘텐츠 편집" 줄은 높이 84px에 버튼 5개가 가득 찼다. 헤더의 `플레이어 수치` 버튼(x447) 자리를 **게임 콘텐츠** 탭으로 바꾸고 허브 페이지를 둔다. 기존 캡션 버튼은 고정 이름으로 계속 동작한다.

```
게임 콘텐츠                                   찾기 [______________] Ctrl+F
[플레이어 ] [소환수  ] [몬스터  ] [아이템  ] [장비    ] [상태이상]
[화면·연출] [사운드  ] [대사    ] [번역    ] [아트    ] [플레이테스트]
[모든 수치]   최근: 가죽 갑옷 · 해골 궁수 · 기절          고정: ★ 질풍 도약
```

- **타일**: 2×6, 약 96×40px다. 미저장과 경고 수를 배지로 보여 준다.
- **찾기**: 에셋 이름, 표시 이름, 한글 라벨, 코드 필드 이름을 함께 검색한다. 결과를 누르면 소유 화면의 그 필드로 바로 간다.
- **최근·고정**: 기존 PlayerPrefs `Workshop.Pinned.*`를 재사용한다. 작업대에는 [게임 콘텐츠 ▶]와 최근 3개만 남긴다.
- **비연결 상태**: Authoring이 아니면 타일을 흐리게 보여 준다. "프로젝트 연결 필요"와 함께 [프로젝트 연결] 또는 [기본 작업 공간으로 전환] 버튼을 둔다.
- **연결 이동** (P3부터): 방 편집에서 배치한 적을 고르면 "몬스터 화면에서 열기"가 나온다. 전투 설정에서 군집 이름을 누르면 군집 탭으로 간다.

### 5.2 공용 목록-상세 골격

모든 도메인 화면이 같은 좌표와 같은 조작을 쓴다. UIResolution 검사는 이 골격을 한 번 검증한다.

```
y0~30   헤더: 기존 탭 · 게임 콘텐츠 · [미저장 2 ▾]
y33~51  [하위 탭: 기본|효과|등장]                    검색[________] [필터 ▾]
y56~276 목록 (행 22px × 10)          │ 상세 (ScrollRect)                    │ 미리보기·경고
        ▌가죽 갑옷        ●          │ 이름  [가죽 갑옷_____] [원본][사용처 3]│ 툴팁 문구
        ▌금 간 숫돌      ⚠           │ 등급  [1][2][3][4]   600 골드         │ 0강 → 3강 요약
        ▌질풍 도약  등장 꺼짐         │ 최대  [- 3 +]          원본 2  ↺       │ ⚠ 설명과 수치
          └ 내 복제본                 │ 효과 1. 능력치 보정  [▲][▼][✕]        │   불일치 → 이동
y280~296 [+ 새로][복제]  ◀ 1/2 ▶     │ 설명 줄: 공격력 · % · 0~100 · atkPercent│ [미리보기 ⤢]
y299~321 [변경 취소][프리셋][표 보기][모든 필드]        [시험 F6 ▾][프로젝트에 저장 Ctrl+S]
y335     저장됨 · 주머니 효과는 다음 습득부터, 상점 가격은 다음 상점 생성부터
```

- **목록**: 배지 종류는 ● 미저장, ⚠ 경고, 민트 점(DATA 변경), "등장 꺼짐", "복제본"이다.
  - 미저장 상태로 다른 항목에 가도 초안이 유지된다(DraftStore).
  - 필터를 바꿔도 행이 제자리에서 사라지지 않는다.
  - 필터 칩은 [필터 ▾]로 접어 검색칸 폭을 확보한다.
- **상세**: 필드 메타데이터로 자동 배치하고, 좌표를 필드마다 하드코딩하지 않는다.
  - 바뀐 칸은 민트색이고 옆에 **원본값**을 작게 표시한다. 용어는 "원본값"으로 통일한다. 지금은 화면마다 "기본값"이 프리팹 값, 에셋 값, 코드 초기값으로 뜻이 다르다.
  - 상세 아래의 고정 설명 줄 하나가 마우스를 올렸거나 포커스한 필드의 설명·단위·범위·코드 이름을 보여 준다. 행에는 호버 판정용 투명 영역을 둔다.
- **미리보기 열**: 158px라 실제 위젯을 1:1로 넣을 수 없다. 주머니 상세 원본은 244×414이고, UI 원본 1px = 논리 1px 규칙이라 축소할 수도 없다. 그래서 이 열은 문구 수준(툴팁, 강화 요약, 결과 카드)과 경고 목록만 맡는다. 경고를 누르면 그 필드로 스크롤하고 강조한다.
  - [미리보기 ⤢]는 Esc로 닫는 전체 화면 오버레이에 실제 위젯을 1:1로 띄운다. 가격 계산 같은 문맥은 더미로 채운다.
  - 월드에 그리는 연출(타격, 피해 숫자, 월드 패스)은 시험 중 F7에서만 재생한다.
- **표 보기**: 640px 폭에서 열을 묶음 탭으로 나눈다. 예: 소환수 [스킬][자동 공격][대쉬], 몬스터 [능력치][파생].
  - 아이콘·이름 열은 고정하고, 숫자 열은 묶음당 7개(약 48px) 이하로 둔다.
  - 칸을 누르면 그 칸 위에 편집 팝오버 하나가 뜬다(−/+, 직접 입력, Enter 확정, Esc 취소). 머리글을 누르면 정렬한다.
- **단축키**: 페이지 등록표 한 곳에서 처리하고, 상태 줄에 한 줄로 안내한다.

| 키 | 동작 |
|---|---|
| Ctrl+S / Ctrl+Shift+S | 포커스 입력을 확정한 뒤 현재 항목 저장 / 모두 저장 |
| Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z | 문서 실행 취소·다시 실행. 입력칸 포커스 중에는 입력칸이 처리한다 |

| F6 / Shift+F6 | 시험 시작·복귀 / 로드아웃 설정 열기 |

### 5.4 시험 연동

- **시험 왕복 계약**:
  - 콘텐츠 화면의 [시험 F6]은 열린 방이 아니라 **시험장** 방 문서를 Draft로 넘겨 시작한다. 시험장은 전투 없는 빈 방에 허수아비 하나를 둔 방이다.
  - 돌아오면 `WorkshopSession`이 보던 화면과 선택을 되살린다.
  - 미저장 초안은 "미리 적용"으로 시험에 반영되고, 상태 줄에 "미저장 초안으로 시험 중"이 뜬다. 돌아와도 ● 배지가 남는다. 실험값을 보려고 팀 공유 DATA에 매번 저장할 필요가 없다.
- **허수아비**: 지금은 `Monster ` 접두 필터 때문에 배치 목록에서 빠진다. P1에서 카탈로그에 넣는다.
- **로드아웃 하나**:
  - 모든 시험(방·층·마을)이 "게임 설정"의 **시험 장비** 칸 하나를 쓴다. 아이템, 장비와 강화 단계, 소환수 슬롯이 들어간다. 제작실 시험에서는 `VillageDebugLoadout` 대신 이것을 쓴다.
  - F6은 마지막 로드아웃에 지금 보는 항목을 자동으로 더한다. Shift+F6이나 [시험 F6 ▾]로만 설정 창을 연다.
- **도구막대**(`WorkshopReturn` 확장): [지급·장착] [적 소환·제거] [상태이상: 가까운 적 / 모든 적 / 플레이어] [무적] [일시정지] [튜닝 F7] [편집으로 F6].
  - 상태이상 부여는 `LEVEL_WORKSHOP` 빌드에서도 컴파일되는 경로를 새로 만든다. `StatusDebugKeys`는 Development 빌드 전용이다.
  - 전투 클릭 차단(`IsCombatPointerBlocked`)은 지금 F6 버튼 사각형 하나뿐이다. 이를 도구막대와 열린 패널의 사각형 목록으로 바꾼다. 그러지 않으면 버튼을 누를 때 공격도 나간다.
- **튜닝 오버레이 F7** (P6):
  - 비모달이다. 이동은 유지하고 포인터는 패널 안에서만 잡는다(`LightingDebugPanel` 방식).
  - 상세 화면에서 핀을 단 필드를 보여 준다. 핀이 없으면 최근에 고친 4개를 보여 준다.
  - F8 조명은 F7의 "조명" 탭으로 흡수하고, F8은 그 탭의 단축키로 남긴다.
  - Authoring이면 오버레이 안에서도 Ctrl+S로 저장한다. 마을 편집 패널과 같은 관례다.
