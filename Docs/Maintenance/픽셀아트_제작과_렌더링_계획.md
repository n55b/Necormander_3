# 픽셀아트 제작과 렌더링 개선 계획

현재 PC 기준으로 A1~F4 검수를 마쳤다. E4의 내장 GPU 실기기 측정은 별도 일정으로 보류한다. 단계별 구현과 실제 재생 결과는 [렌더링 검수 결과](픽셀아트_렌더링_검수.md)에서 확인한다.

2026-11-21 작업본 기준. 기준 화면은 640×360이다. 이 계획의 첫 산출물은 마을에서 주인공과 적이 마주 선 장면이다. 그 한 장면에서 인물의 크기와 윤곽, 조명 아래의 얼굴, 공격 예고, 맞는 순간의 파편, 한글 피해 숫자를 함께 승인할 수 있어야 한다. 같은 장면을 재생해 이후 수정의 품질과 비용을 비교한다.

## 1. 원본에서 화면까지 추적하는 아트 검사

각 행을 **ARTIST 원본 → 실제 임포터·스프라이트 서브에셋 → 프리팹·씬 경로 → 애니메이션 프레임 → 640×360 캡처**로 연결한다. 아티스트에게는 실제 모습과 수정할 원본을 나란히 보여준다. AI와 빌드 검사는 같은 결과를 GUID, local ID, 계층, 필드, 관측값, 기대값, 예외 사유가 있는 JSON으로 읽는다.

- 밀도는 기본 카메라에서 원본 한 픽셀이 차지하는 논리 픽셀의 가로·세로 길이로 기록한다. 회전 없는 직교 카메라에서는 `(360 / 세로 월드 시야) × 월드 배율 / PPU`로 점검한다. 회전·비균일 부모·격자 변환은 스프라이트의 두 로컬 축을 실제 렌더 카메라로 투영한다. 원본 자체가 이미 2배 이상 확대되어 저장됐는지는 반복 블록과 사람의 육안 판정을 함께 쓴다.
- 원본에서 색 경계, 알파 가장자리와 여백을 검사한다. 임포트 결과에서는 플랫폼 축소·압축, sRGB 용도, 피벗, 9분할, 타일 시트 패딩과 아틀라스 회전·패킹을 확인한다. 씬에서는 상위 배율, 변형 프리팹, Animator 스케일 키, 생성 코드, 재질의 텍셀 오프셋과 UI Canvas 배율을 추적한다.
- 우선순위는 전투 중 인물과 공격 판독을 해치는 결함, 반복해서 보는 환경·HUD 결함, 사용 경로가 불분명한 원본 순서다. 원본 그림에 들어간 중복 픽셀, 화면의 작은 글리프, 조명을 위한 연속값 텍스처에는 서로 다른 판정 기준을 둔다.
- 완료 조건은 활성 렌더러 전부에 수정 경로나 이유 있는 예외가 있고, 필수 씬에서 새 미분류 에셋과 잘못된 임포트가 검증 도구에 실제로 잡히는 것이다.

## 2. 기준 장면과 아트 정리

1. 마을에서 주인공·양손·허수아비·일반 적·대형 적·나무·울타리·HUD를 같은 기본 줌으로 캡처한다. 원본 1배와 3배 최근접 확대판에 발 높이, 윤곽 굵기, 눈·무기 끝·손 사이 여백을 표시한다. 밝은 바닥, 어두운 바닥, 횃불 앞에서 각각 읽혀야 한다.
2. 기준은 주인공 몸과 손의 실제 밀도다. 일반 적의 주요 외곽은 기본 줌에서 1논리 픽셀을 출발값으로 잡는다. 내부선은 명도차와 선택적인 어두운 색을 사용한다. 보스는 같은 밀도에서 실루엣과 몸체가 크게 보이도록 설계한다. 더 굵은 강조선이 필요한 형상은 기준 장면과 함께 예외를 기록한다.
3. 대표 적 한 종은 원본, 배치, 재질을 따로 바꿔 비교한다. 손실 없는 정수 역확대가 가능한 그림은 원본을 복원하고, 불규칙한 축소로 눈이나 손가락이 사라지는 그림은 목표 크기에서 다시 그린다. 회전하는 표식·기하 효과는 벡터 실루엣과 화면 기준 외곽선 셰이더를 사용한다. 수작업 캐릭터의 표정과 내부 명암은 원본에서 관리한다. 이미 그려진 선과 셰이더 선이 겹치는 재질을 분리한다.
4. 교체 단위는 캐릭터·타일셋·UI 가족이다. 기준 자세를 먼저 검수한 뒤 같은 계열의 모든 애니메이션을 재생해 프레임 사이 윤곽이 기어가거나 피벗이 튀는지 확인한다. 수정은 ARTIST 원본부터 반영하고 슬라이스 ID, 프레임 순서, 피벗과 아트 출력을 보존한다. 루트 배율을 바꿀 때 발 접점, 충돌체, 공격 거리, 소켓, 그림자와 체력바 위치를 이전 값과 대조한다.
5. 이후 일반 적·소환수 → 엘리트·보스 → NPC·환경·타일 → HUD·메뉴·아이콘 순으로 확대한다. 환경은 타일 셀의 월드 면적과 충돌을 유지하며 그림 밀도를 조정한다. UI는 기본 표시 크기에서 1~2색 실루엣과 아이콘 안쪽 여백을 검수한다. 기본 줌과 전투 줌을 모두 재생한다. 퇴역 자료는 참조를 이관한 뒤 프로젝트 루트 Legacy에 보관한다.

| 초기 라이브러리 | 대사 한 글자 드러내기와 구두점 쉼, 낮은 속삭임 파동, 경고 문구의 두 박자 강조, 버튼 선택의 1픽셀 들림, 획득 알림, 체력 회복 상승, 일반 피해의 짧은 충격, 치명타의 멈춤·반동, 콤보 숫자의 교체·복귀를 제공한다. 각 효과의 마지막 프레임에서 원래 글자 폭과 위치를 복원한다. |
| 편집·이관 | Sunyunie Panel에서 한글·영문·숫자·아이콘이 섞인 같은 문장을 재생·정지·한 프레임씩 진행한다. 기존 대사 태그는 어댑터로 해석하고 피해 숫자부터 이관한다. 번역, TMP 리치 텍스트, 조합 글자·공백, 동적 줄바꿈, 풀 재사용, 빠른 클릭, 모션 감소를 회귀 검사한다. |

## 4. URP 2D 조명·안개·후보정

- **프로필 적용 순서**는 프로젝트 기본값 → 씬·바이옴 → 방·로컬 영역 → 일시적인 전투 연출이다. 각 단계는 바꿀 필드, 우선순위, 블렌드 시간과 복귀 조건을 가진다. 패널에서 현재 카메라, 영향을 주는 방, 최종 값과 그 출처를 확인한다. 씬 전환·재입장·추가 카메라 시 전역 셰이더 값이 남지 않는지 검사한다.
- **조명과 그림자**는 Light2D의 환경광과 국소광, 기존 동적 그림자를 연결한다. 횃불 가까이서 광원 방향이 손·NPC의 그림자와 일치하는지 확인한다. 피격 섬광·무기·포탈은 이미시브 마스크로 선택 발광시키고 국소광에는 동시 활성 예산과 거리 우선순위를 둔다.
- **안개**는 월드 좌표에 고정되는 저층 안개, 나무 사이의 빛줄기, 전경에서 주인공을 가리는 국소 안개를 각각 조절한다. 타일 종류·벽·방 경계를 마스크로 써서 복도와 실내로 안개가 새지 않도록 한다. 밀도는 부드럽게 변화시키고 색 단과 가장자리는 논리 픽셀에서 팔레트 디더링한다. 안개 속에서도 바닥의 공격 예고와 플레이어 얼굴이 먼저 읽혀야 한다.
- **합성 순서**는 월드 지형·라이트·그림자와 Y 정렬 → 월드 이펙트 및 발광 추출 → 안개·제한된 Bloom·팔레트 보정 → HUD·텍스트 → 최종 Point 확대를 기준으로 비교한다. 바닥 전조나 캐릭터 뒤 파티클처럼 깊이가 필요한 것은 해당 월드 정렬 구간에 그린다. 현재 정렬 레이어 텍스처와 URP 2D Renderer에서 실제 패스 순서를 Frame Debugger로 확인한 후 전용 패스를 도입한다.
- 첫 프리셋은 **횃불과 엷은 저층 안개가 있는 마을**, **차가운 후면광으로 전조가 잘 보이는 던전**, **포탈 중심만 밝게 남는 전환**이다. 각 장면에서 안개·그림자·발광을 개별 비교하고 HUD 글자와 바닥 경계의 선명도가 유지되는지 캡처한다.

## 5. GPU 파티클 관리와 최적화

| 영역 | 첫 적용 | 운영 원칙 |
| --- | --- | --- |
| 환경 | 먼지, 포자, 낙엽, 횃불의 재, 안개 속 반딧불 | 방·시야 단위로 방출하고 멀어진 방은 휴면시킨다. 바람·광원은 분위기 프로필을 공유한다. |
| 전투 | 타격 방향의 금속·목재 파편, 방어막 균열, 마법탄 꼬리, 강타·처치 폭발 | 중요한 피격과 위험 전조용 용량을 예약한다. 연타는 같은 지점·시간대의 요청을 병합한다. 타격 위치와 방향은 확정된 피해 이벤트에서 받는다. |
| UI | 버튼 눌림, 아이템 획득, 체력 알림, 글자 강조 | 640×360 캔버스 좌표, 패널 클리핑과 UI 정렬을 지원한다. 메뉴 일시정지 중의 시계와 인게임 시계를 분리한다. 입력 판정에 참여하는 오브젝트 수를 늘리지 않는다. |

공용 방출 요청은 프리셋 ID, 위치·방향, 시드, 우선순위, 좌표계, 시간 기준과 수량을 전달한다. 백엔드는 팔레트·재질·정렬 묶음별로 모아 그린다. 위치·속도·수명은 소수점으로 유지하고 화면에 출력할 때 정수화한다. 환경·전투·UI에 같은 요청을 재생할 수 있는 시료를 먼저 만든다. 단순 궤적의 버텍스 셰이더 방식과 반복 충돌·흐름장을 처리하는 Compute 방식을 같은 시드와 화면 점유율에서 비교한다. 각 효과에 적합한 백엔드를 택할 수 있도록 요청 형식은 공유한다.

지형 반응은 방 생성 시 만든 저해상도 점유·거리장과 표면 방향을 공유한다. 단순 먼지는 충돌 계산을 생략하고, 튀어야 하는 파편에만 충돌을 배정한다. 화면을 많이 덮는 반투명 도형은 입자 개수와 별도로 픽셀 면적과 오버드로를 제한한다. 예산 초과 시 시야 밖 방출 → 먼 배경 → 오래된 장식 입자 순으로 줄인다. 패널에는 요청·실제 방출·생략 수, 활성 입자, 버퍼 포화, 드로우콜과 GPU 시간을 표시한다. GPU 시간이 제공되지 않는 환경에서는 미측정으로 표시한다.

### 기존 검증과 새로 필요한 검증

기존 진입점은 `Tools/Invoke-UnityVerification.ps1`이다. A 단계에서 `-Suite Assets`로 에셋 기준선을 저장한다. B·F에서는 `Presentation`, `World`, `Combat`으로 화면·지형·공격을 확인하고 C에서는 `Typography`로 한글·영문과 UI를 검사한다. F의 마지막에는 `-Suite Baseline -CompareTo <기준선의 asset-inventory.json> -IncludeWindowsBuild`로 참조와 빌드 결과를 대조한다. 실제 도트 밀도 추적, 글리프 메시 재생성 계수, 안개·발광 패스 캡처, 입자 포화·GPU 시간 검사는 이 계획에서 추가할 항목이다. 자동 수치와 함께 1배 재생 영상을 남겨 실루엣과 타격 가독성을 검수한다.

**성능 목표 초안.** 기준 PC와 내장 GPU급 하한 기기 사양을 A 단계에서 기록한다. 60fps를 목표로 제안하며, 60초 혼전에서 CPU·GPU 각각 p95 13.3ms 이내, 프레임 p99 16.7ms 이내를 첫 예산으로 삼는다. 프레임 평균과 별도로 첫 타격, 방 진입, 보스 마무리의 최악 프레임·GC 할당·셰이더 준비를 본다. 같은 경로에서 효과를 끈 상태와 세 품질 단계를 비교하고, 저사양에서 낮춰도 적의 전조와 명중 확인은 남아야 한다. 기존 단일 PC 측정은 기준 참고치이며 최저 사양 성능은 별도로 측정한다.

**측정 출발점.** 직전 Windows 개발 빌드에서 D3D11, 1280×720 창, 구간당 480프레임을 측정했다. 연속 프레임 사이 경과 시간 p95는 마을 이동 2.62ms, 허수아비 연타 2.96ms, 시드 907 던전 1.25ms였다. 허수아비 연타의 최악 프레임은 22.51ms로 60fps 한 프레임 예산을 넘었다. 이 실행에서 GPU 시간은 수집되지 않았다. GPU 파티클 밀도를 결정하기 전 하한 기기에서 GPU 프로파일과 오버드로를 확보한다.

**작업자가 찾을 곳.** 기존 ARTIST 동기화, PixelSpriteImportPolicy, PixelText, TMPTextEffectPlayer, WorldAtmosphere, GroundShadowField, WorldSparkField가 각 변경의 출발점이다. Sunyunie Panel에는 아트 검사, 텍스트, 분위기, 파티클의 네 작업 화면을 둔다. 각 화면은 실제 원본·프리셋 선택, 현재 값의 출처, 장면 미리보기, 해당 회귀 검사까지 연결한다. 예외와 프리셋에는 단위·허용 범위·기본값이 있으며, 다음 작업자는 문구 검색이나 씬 전체 탐색 없이 값을 조정할 수 있어야 한다.
