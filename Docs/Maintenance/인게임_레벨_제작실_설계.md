# 인게임 레벨 제작실 설계

플레이 모드 저장을 실제 게임 콘텐츠와 연결하고 팀 제작 데이터를 나누는 다음 단계는 [DATA 프로젝트 저장·협업 계획](../../DATA/README.md)에 정리했다.

**첫 출시 목표는 기획자가 Windows 게임을 열어 기존 방을 복제하고, 문과 전투를 바꾸고, 그 방을 직접 클리어한 뒤 동료에게 넘기는 것이다.** 첫 비교 대상은 `MapDesign`에서 사용하며 실제 일반 방 후보에도 등록된 `Room_Normal 3`이다. 방 하나에서 이 작업을 끝까지 검증한 뒤 튜토리얼, 특수방, 층 생성, 마을로 넓힌다.

아래 시간·성능 수치는 팀 사용성 검수를 위한 목표치다. 현재 팀의 작업 시간과 불편의 빈도는 0단계에서 관찰해 기록한다.

첫 사용자는 팀 기획자와 아티스트로 가정한다. 공유 단위는 동료가 같은 게임 빌드에서 열 수 있는 제작 파일이다. 공개 레벨 탐색·온라인 게시·동시 편집은 공개 제작 모드의 대상과 운영 방식을 정할 때 별도로 설계한다.

## 현재 제작 빌드

**내 작업**에서 방 복제, 이름 변경, 타일 네 레이어, 문 방향, 고정 적·소품 배치, 되돌리기, 입구·지점 플레이, 복귀, 저장·공유를 사용할 수 있다. **게임 설정**은 절차 층의 조절값, 시드별 방 그래프, 위치별 제작 방 연결, 튜토리얼·엘리트·마을 시험 진입점을 제공한다. **Legacy**에는 기존 방과 팀 도구를 보존한다. 새 방을 게임 원본에 등록하기 전에 Unity에서 별도 프리팹 변형으로 가져올 수 있다. 조작과 저장 위치는 [툴 사용 가이드](../Guides/툴%20사용%20가이드.md)에 있다.

방 작업대에서 소품·적을 묶어서 옮기거나 지우고, 타일 무늬는 이름을 붙여 다른 방에서 다시 쓸 수 있다. 전투 방은 최대 8개 웨이브의 적 군집과 순서를 저장한다. 일반 방은 클리어 보상을 지정할 수 있다. 이 설정은 단독 시험, 층에 연결한 방, Unity 프리팹 변형에 공통으로 적용된다.

튜토리얼은 시작·종료 방 사이의 순서를 바꿀 수 있다. 변경한 방 연결은 새 경로를 따라가며 실제 생성기로 문 방향과 겹침을 검사한다. 마을에서는 상호작용 NPC의 위치와 표시 상태, 여러 줄 인사말, 분위기와 조명을 직접 시험하고 저장한다. 개별 방은 JSON으로 공유하고, 층·마을과 저장된 방은 `.levelpack`으로 전달한다. 수신자는 항목별로 내 저장본과 팀 공유본을 비교해 새 작업 공간을 연다. 묶음을 주고받을 때 이전 개정의 해시로 양쪽 수정 여부를 구분한다. 두 실기기에서 팀원이 직접 이어받는 사용성 검수가 남아 있다.

### Windows 검증 결과

Ryzen 9 9950X3D·RTX 4060 Ti에서 Windows 제작실을 1280×720으로 열고 시드 907의 `Room_Normal 3`으로 왕복했다. 마우스 버튼을 놓을 때부터 새 씬의 페이드가 끝나고 조작할 수 있을 때까지 첫 진입 1,175ms, 첫 복귀 425ms였다. 이후 20회의 p95는 진입 905ms, 복귀 422ms였다. 매 복귀 시 카메라 3개, 타일맵 4개, 제작실 렌더 타깃 1개, 월드 파티클 ComputeBuffer 1개, 명중 이벤트 구독 1개였다. 씬이 끝난 뒤 세 전투 효과 풀에 남은 객체는 매번 0개였다.

이전 버전에서는 20회 왕복 후 강제 GC를 거친 관리 메모리가 1.21MiB 증가했다. 개발용 플레이어에서 첫 복귀와 마지막 복귀의 힙을 대조한 결과, 공용 `MapToggle` 액션의 콜백에 지난 씬의 지도 UI가 남았다. 이 경로로 지도 UI 10개, 플레이어 컨트롤러 10개, TMP 라벨 50개가 추가로 유지됐다. 지도 UI는 이제 활성화 중에 구독한 액션을 직접 저장하고 비활성화될 때 같은 액션에서 해제한다. 마지막 전투의 GameManager, 인벤토리, 장비 인벤토리와 증강 선택창도 파괴 시 자신의 정적 참조를 해제한다. HUD는 초기화할 때와 파괴될 때 이전 체력·인벤토리에서 구독을 해제한다.

제작실은 URP의 `UNIVERSAL_PROFILING_NO_ALLOC` 빌드 옵션을 사용한다. 제작실과 시험 씬을 반복해 열 때마다 생성되는 카메라에는 공용 프로파일링 샘플 이름이 표시된다. 힙을 다시 검사할 때는 `WorkshopBuild.BuildMemoryCheckPlayer`로 개발용 플레이어를 만들고 `-workshopSoak -workshopHeapSnapshots -workshopReport <결과 폴더>`로 실행한다. `workbench-0.snap`과 `workbench-20.snap`은 Unity Memory Profiler에서 열 수 있다. 프레임 시간은 스냅샷을 끈 일반 QA 빌드에서 측정한다.

최종 개발용 빌드에서 첫 복귀와 20번째 복귀의 지도 UI와 플레이어 컨트롤러는 각각 0개, TMP 라벨은 각각 53개였다. 카메라 프로파일링 항목도 1개로 일정했다. Memory Profiler가 참조를 추적한 관리 객체의 순증가는 수정 전 974,634바이트에서 수정 후 24,170바이트로 줄었다. 별도의 일반 QA 빌드에서는 강제 GC 후 13,459,456 → 13,586,432 → 13,635,584바이트로 20회간 172KiB 증가했고, 머티리얼 128개·메시 37개·렌더 텍스처 16개가 유지됐다. 같은 실행에서 예열 후 진입·복귀 p95는 각각 912ms와 424ms였다. 유형별 원자료는 `Logs/Verification/WorkshopMemory/heap-comparison.csv`, 시간과 GC 측정은 `complete-windows/soak`에 있다.

바닥 타일 수 기준 가장 큰 `Room_Boss`(2,100칸)에서는 브러시를 옮긴 다음 표시 프레임에 지도 픽셀이 바뀌었다. 32×32 도장을 찍어 1,024칸이 반영되는 데 입력 재생 포함 15.73ms, 개별 도장 50회에 0.451초, 연속 실행 취소 50회에 1.070초가 걸렸다. 마지막 방 JSON과 디스크 자동 복구본은 모두 첫 문서와 일치했다.

Unity 6000.0.59f2, RTX 4060 Ti, D3D11 환경에서 640×360, 1280×720, 1366×768, 1920×1080 창으로 마우스 입력을 보냈다. 각 창에서 타일 한 획 취소·복원, 동쪽 문 이동, 고정 적 배치, 공유본 가져오기, 저장본 다시 열기, 실제 BattleScene에서 고정 적 처치와 방 클리어, 편집 복귀를 검사한다. 처치는 검증기가 게임의 피해 함수를 호출한다. 게임 설정에서는 튜토리얼 방을 격자 위치에 연결해 실제 일곱 방 경로로 시작한다. 종료 시 일반 런 저장, 선택 기술과 튜토리얼 완료 값이 시작 전과 같은지 검사한다.

기존 방 32개의 문서 왕복과 오브젝트 참조, 타일·출구·고정 적을 변경한 새 프리팹 변형의 재임포트 및 원본 보존을 확인했다. 던전 배치 회귀와 파일 저장 호환 검사도 통과했다. 증거는 `Logs/Verification/LevelWorkshop`에 있다.

Unity 2D Animation 10.2.1의 `GpuDeformationSystem`은 첫 씬에서 스프라이트 변형용 예비 버퍼를 만들며, 변형 시스템을 사용하지 않는 플레이어에서는 종료 시 버퍼가 남았다. `Packages/Local`의 UPM 패키지는 할당 시 기존 해제 함수를 종료 이벤트에 등록하고 해제 시 등록을 푼다. 공식 10.2.1 압축본의 SHA-256은 `128f7d0095e84adcb51a95fad8ce699d90b627276d0ee06f38de3e3a0943f14e`다. 1,967개 항목을 대조해 확인한 유일한 파일 변경은 [종료 처리 패치](../../Packages/Local/2d-animation-fallback-lifetime.patch)에 있다. Unity 패키지를 올릴 때에는 새 공식 버전으로 제작실을 종료해 같은 경고를 검사하고, 공식 수정이 포함됐으면 로컬 의존성을 교체한다.

방 편집 확장판은 같은 네 창 크기에서 도장 보관함 저장·재사용, 묶음 이동과 한 번에 되돌리기, 전투 웨이브 순서 변경과 공유본 재열기를 통과했다. 실제 전투에서 고정 적 처치 후 두 군집이 차례로 등장하고, 아이템 보상 설정이 층 배분 뒤에도 유지되며, 마지막 군집 처치 후 출구가 열렸다. Unity 검사에서는 이전 형식 방의 변환, 타일 색·반전과 전투 설정이 들어간 프리팹 변형, 튜토리얼·일반·엘리트·보스 층 생성을 확인했다. 결과와 640×360 화면 캡처는 `Logs/Verification/WorkshopEncounterFinal`에 있다.

튜토리얼·마을 편집 검사는 연결한 방을 다른 순번으로 옮긴 뒤 실제 튜토리얼에서 그 방의 새 위치를 대조한다. 마을에서는 안내 NPC를 켜고 지도에서 옮긴 뒤, 기본 아틀라스 밖의 한글이 포함된 두 줄 인사말과 태양 밝기를 저장한다. 씬을 다시 열어 NPC·대사·조명을 복원하고 일반 런 저장과 해금 상태를 대조한다. 화면 캡처, 해상도별 검사 기록과 Unity 회귀 로그는 `Logs/Verification/WorkshopVillageRelease`에 있다.

팀 전달 검사는 별도의 제작실 저장 위치 두 곳에서 묶음을 주고받으며 수행한다. 수신자가 실제 튜토리얼을 열어 원래의 방 ID로 연결되는지 확인하고, 동일한 방의 클리어 보상을 양쪽에서 다르게 변경해 각 개정을 새 작업 공간에 적용한다. 별도 Windows 프로세스로 같은 전달 파일을 처음 받은 뒤 마을을 플레이하고, 프로그램을 다시 시작해 선택한 작업 공간과 NPC·조명이 복원되는지도 검사한다. 결과 폴더는 `Logs/Verification/WorkshopTeamHandoff`다.

## 1. 현재 제작 경로와 이관 범위

| 현재 확인한 제작 경로 | 기획자가 겪을 수 있는 문제 | 인게임에서 제공할 작업 |
| --- | --- | --- |
| `MapDesign.unity`에 일반 방·플레이어·매니저·HUD가 함께 배치되어 있다. 방 폴더에는 기본본, 변형, 테스트용, 튜토리얼을 포함해 프리팹 32개가 있다. | 파일명만 보면 원본과 변형의 관계, 시험 중인 방, 실제 출현하는 방을 구별하기 어렵다. 씬 인스턴스 수정과 프리팹 원본 수정의 결과도 다르다. | 방 썸네일에 종류, 원본, 사용 층, 출구 방향, 초안 상태를 표시한다. ‘이 방 복제’와 ‘공용 원본 수정’의 영향을 각각 보여준다. |
| `RoomInstance`가 바닥·벽·그림자·통행 불가 타일맵, 문 앵커와 이벤트를 참조한다. 일부 이벤트와 미니맵 아이콘은 자식 이름도 조회한다. | 문 그림을 옮겨도 반대편 연결이나 적 등장 금지 구역까지 맞았는지 알기 어렵다. | ‘문 놓기’ 한 번으로 방향·안쪽 깊이·도착 위치·금지 구역을 미리 본다. 편집 결과로 충돌, 미니맵과 지형 그림자를 갱신한다. |
| `RoomPrefabData.asset`은 8종에 걸쳐 후보 17개를 등록하며 일반 후보는 10개다. `MapGenerationData.asset`의 튜토리얼 경로는 별도로 7개다. 현재 1층에는 층별 덮어쓰기가 있고 3층에는 보스가 지정돼 있다. | 방을 완성해도 특정 층에 등장하지 않는 이유를 찾으려면 여러 에셋을 대조해야 한다. | 방 목록에서 ‘어디서 사용 중인가’를 역조회한다. 층 카드에서 기본값, 층별 변경값, 최종 방 수와 보상을 나란히 보여준다. |
| `NormalRoomEvent`가 군집 추첨, 웨이브 합치기, 스폰 예고, 문 앞 제외를 처리한다. 튜토리얼에는 지정 위치의 몬스터도 있다. | 같은 지도에서 적이 어디에 몇 마리 나오는지, 전멸 뒤 어떤 문이 열리는지 편집 화면에서 읽기 어렵다. | 웨이브 카드에서 고정 배치와 군집 추첨을 고르고, 스폰 가능 영역·최종 마릿수·클리어 조건을 지도로 확인한다. |
| `DungeonLayoutPlanner`·`RoomConnectivity`가 배치를 계산하고 `MapGenerator`가 프리팹 생성, 타일 병합, 문과 미니맵을 연결한다. 별도 생성 시험·엘리트·보스 씬과 검사 도구도 있다. | 단독 방에서 성공한 전투가 실제 층에서 문이나 이동 경로 때문에 실패할 수 있다. | ‘여기서 플레이’, ‘입구부터’, ‘이 층 플레이’를 제공한다. 생성 시험·보스·엘리트 시나리오는 재현할 수 있는 시험 프리셋으로 등록한다. |

이 목록은 현재 저장소의 활성 경로를 조사한 결과다. 0단계에서는 기존 담당자가 실제 방을 제작하는 과정을 관찰해 개인 브러시, 자주 복제하는 프리팹, 수동 보정, 외부 도구까지 대조한다. 사용 기능마다 **그대로 지원 / 여러 조작을 하나로 통합 / 자동 계산 / 퇴역 후보** 중 하나와 대체 동작, 대표 원본, 재현 시험을 기록한다. 몬스터·아이템·대사 편집기에서 레벨과 연결되는 일은 배치, 선택, 지역 설정 변경, 원본 사용처 조회까지 포함한다. 공유 몬스터 능력치나 아이템 정의의 편집 권한은 공용 카탈로그에 둔다.

## 2. 기획자가 보는 화면

제작용 Windows 빌드의 메인 메뉴에 **레벨 제작실**을 둔다. Unity에서는 `Tools > Sunyunie Panel`에서 같은 제작실로 진입한다. F8은 기존 조명 패널에 유지한다.

- **작업대**에서 최근 작업, 자동 복구본, 방·층·마을, 팀 공유본을 썸네일로 연다. ‘빈 방’, ‘기존 방 복제’, ‘전투방 틀’로 시작할 수 있다. 문 방향이나 방 종류로 찾고, 썸네일에서 실제 크기와 간단한 동선을 본다.
- **방 편집 화면**은 640×360 논리 프레임을 사용한다. 상단에는 방 이름·저장 상태·플레이를, 하단에는 최근 사용 도구와 즐겨찾기를 둔다. 재료 서랍과 선택 항목의 속성 창은 접을 수 있게 해 좁은 화면에서 작업 영역을 확보한다. 선택한 문 옆에는 방향과 연결 대상, 적 옆에는 소속 웨이브처럼 지금 필요한 값만 표시한다.
- **층 편집 화면**은 방을 카드로 보여준다. 카드를 열면 해당 방으로, 뒤로 가면 같은 층의 위치로 돌아온다. 고정 순서로 잇는 튜토리얼, 후보와 수량을 편집하는 절차 생성 층, 고정 배치로 시험할 층을 각각 명시한다. 생성 미리보기에는 시드, 시작점에서 보스까지의 경로, 막힌 문, 보상·휴식 간격을 표시한다.
- **배치의 손맛**은 커서 아래 실루엣, 붙을 면의 강조, 놓는 순간의 짧은 반짝임과 소리로 만든다. 드래그로 바닥을 칠할 때는 시작과 끝에서만 강하게 반응한다. 방해물 위의 배치 실패는 이유와 가능한 인접 셀을 알려준다. 브러시 선은 중간에 패널을 만나면 거기서 끝난다. 작업 중 카메라 흔들림과 효과 강도는 별도 설정으로 조절한다.
- **입력**은 마우스 좌클릭·드래그로 배치, 가운데 버튼으로 이동, 휠로 커서 중심 정수 확대, 스포이드·지우개·테두리 채우기·사각 선택·복제·다중 이동을 지원한다. `Ctrl+Z`로 한 획을 취소하고 `Ctrl+Shift+Z`로 다시 실행한다. 화면 버튼으로도 같은 작업을 할 수 있다. 키보드 포커스, 패드 셀 커서, 한글·영문 라벨, 모션 감소, 색과 모양을 함께 쓰는 경고 상태를 검수한다.

**첫 사용 과제.** 기획자가 일반 방을 복제해 동쪽 벽에 문을 놓고, 궁수 한 명을 옮긴다. 커서를 입구에 두고 ‘여기서 플레이’를 누른다. 들어가서 전멸시키면 문이 열리고, ‘편집으로’ 돌아오면 방금 선택한 궁수와 확대율이 그대로다. 이어서 문을 막아 보면, 무엇이 잘못됐는지 지도에서 찾고 직전 한 획으로 복구할 수 있어야 한다.

## 3. 편집 데이터와 실제 게임을 연결하는 방법

| 소유 대상 | 기록할 내용과 처리 원칙 |
| --- | --- |
| 방 문서 | 형식 버전, 고정 방 ID와 개정 번호, 로컬 그리드 원점·셀 크기, 희소 타일 레이어, 셀별 타일 ID·색·변환, 오브젝트 인스턴스 ID·위치·방향, 문·상호작용·전투와 완료 조건을 기록한다. 타일 좌표와 층 배치 좌표는 별개다. 소품의 지면 접점은 방의 논리 픽셀 단위를 지원한다. 기존 소수점 피벗·변환을 읽어올 때 일괄 반올림하지 않는다. |
| 층·튜토리얼·마을 문서 | 층은 방 ID와 개정, 후보군, 연결, 기본값 상속과 층별 변경, 보스·보상 조건을 소유한다. 튜토리얼은 순서·진입 조건·종료 포탈을 소유한다. 마을은 고정 지형과 NPC·상점·대화·포탈 참조를 가진 독립 지도다. 스폰 수치가 전역인지 특정 방 전용인지 편집 지점에서 표시한다. |
| 콘텐츠 카탈로그 | 타일, 규칙 타일, 소품, 적·군집, 함정, NPC, 보상, 대사, 분위기 프리셋을 안정 ID로 조회한다. Unity 제작 시 원본 GUID와 서브에셋 ID를 카탈로그에 굽는다. Windows에서는 빌드에 실린 참조를 사용한다. 이름 변경과 ARTIST 그림 수정 뒤에도 같은 ID를 해석한다. |
| 기존 자산 변환기 | Unity 전용 변환기가 기본 프리팹, 변형의 실제 덮어쓰기, 씬 인스턴스의 추가 변경을 구분해 읽는다. 알 수 없는 컴포넌트, UnityEvent, 중첩 프리팹은 원본 경로와 함께 ‘이관 필요’로 표시하고 원본을 유지한다. 참조가 빠진 방은 초안 저장과 복구가 가능하며 팀 적용 전에 해소한다. |
| 게임에 배치하는 경로 | 현재 `DungeonLayout.Room`에는 `GameObject Prefab`이 들어 있다. 먼저 기존 프리팹과 방 문서를 함께 해석하는 어댑터를 만들고, `DungeonLayoutPlanner`·`RoomConnectivity`가 방 ID와 문 정보를 받을 수 있게 한다. 방 생성 시 동일한 `RoomInstance`·이벤트·`RoomTileTransfer`를 사용하고, 기존 `MapGenerator`의 문 연결·NavMesh·미니맵 갱신 순서를 재사용한다. 편집기 미리보기와 게임 빌드가 같은 방 생성 코드를 호출한다. |
| 명령과 파생 결과 | 한 획, 다중 이동, 문 연결은 변경 전후를 가진 명령 한 건이다. 취소하면 타일과 종속 연결까지 돌아간다. 충돌·통행 영역·미니맵·지형 수광면은 문서에서 만든다. 드래그 중에는 바뀐 셀만 미리 그리고, 손을 놓으면 영향 영역을 갱신한다. 전체 경로 탐색과 NavMesh 갱신은 확정 또는 시험 진입 시 한 번 수행한다. |

### 저장, 팀 전달, 정식 반영

1. Windows 빌드는 사용자 데이터의 **제작 프로젝트 전용 폴더**에 방별·층별 JSON을 저장한다. 실행 취소 기록과 자동 복구 초안을 구분하고, 임시 파일 기록 후 교체한다. 앱이 저장 도중 종료돼도 마지막 정상 개정을 열 수 있게 한다.
2. 팀 전달 파일은 방·층 문서, 의존 ID와 개정, 미리보기, 형식 버전을 묶는다. 팀원은 다른 PC에서 열어 ‘이 방에서 쓰는 군집이 이 빌드에 없음’처럼 해석할 수 없는 참조를 확인한다. 지원 범위를 넘는 파일과 잘못된 좌표는 가져오는 단계에서 진단한다.
3. 저장소에 반영할 원본은 방마다 파일 하나를 갖고 셀·객체 순서를 고정해 Git 차이를 읽을 수 있게 한다. Unity 쪽 가져오기는 변경 내용을 먼저 보여준다. 같은 기본 개정에서 두 사람이 같은 문을 바꿨으면 양쪽 버전을 보존해 선택하게 한다. 서로 다른 방은 독립적으로 반영한다.
4. 정식 적용은 검증된 방 개정을 후보 목록이나 고정 경로에 연결하는 작업이다. 단순 저장만으로 기존 층의 출현 후보가 바뀌지 않게 한다. 원복은 직전 카탈로그와 방 개정을 함께 선택한다. 아트 원본은 계속 ARTIST에서 관리한다.

### 즉시 플레이와 복귀

‘여기서 플레이’는 현재 초안을 메모리에 찍고, 위치를 유효한 바닥에 표시한 뒤 **분리된 시험 세션**에서 실제 플레이어·손·펫·문·적·상점을 실행한다. ‘입구부터’는 진입 트리거와 스폰 예고를, ‘이 층 플레이’는 방 사이 이동과 보상 흐름을 시험한다. 공간 편집에는 사전 계산한 시드를 사용하고 전투 시험에는 별도의 난수 상태를 두어 같은 입력 조건을 재현한다.

편집·시험·팝업에 입력 소유권을 하나씩 준다. 시험 시작 전 편집 카메라, 선택, 도구, 실행 취소 위치를 기록한다. 정지·사망·층 이동·보스 처치·재시작 경로 모두에서 시험 엔티티, 풀, 이벤트 구독, 시간 배율, 조명 덮어쓰기를 정리한다. 런 세이브와 튜토리얼·해금 PlayerPrefs에는 시험용 저장소를 주입한다. 시험 중 주운 골드나 처치한 적은 설계 문서에 기록하지 않는다.

복귀할 때는 플레이어의 이동 경로와 사망·클리어 지점, 웨이브별 소요 시간을 선택적으로 지도에 겹쳐 본다. 예를 들어 궁수를 옮긴 뒤 같은 입구·장비·시드로 재도전해, 첫 화살을 피할 공간이 생겼는지 직접 비교한다. 동료에게 재현 정보를 넘길 때는 빌드 버전, 방 개정, 층, 시드와 시작 위치를 함께 담는다.

## 5. 검수 과제와 측정 기준

- **처음 쓰는 기획자**가 도움 없이 5분 안에 방을 복제해 문 하나와 적 하나를 수정하고 직접 플레이하는 것을 첫 목표로 둔다. 기존 사용자에게 같은 과제를 주어 시간, 파일 탐색 횟수, 오류 복구 성공 여부를 비교한다. 저장한 방을 다른 기획자가 열어 출현 층과 클리어 조건을 설명할 수 있어야 한다.
- **제작 중 진단**은 오류를 클릭하면 해당 셀·문·카드로 이동하게 한다. 반대편 문 없음, 문 앞 적 스폰, 도달 불가능한 보상, 종료 포탈 없음, 층별 수량 충돌을 의도적으로 재현한다. 잘못된 배치는 초안으로 남길 수 있고 ‘층에 적용’ 시에는 진행을 막는 오류를 해결해야 한다. 자동 수정은 전후 위치를 보여주며 한 번에 취소할 수 있다.
- **화면과 입력**은 네 창 크기 640×360, 1280×720, 1366×768, 1920×1080에서 모서리 셀, 확대 중심, UI 위 드래그, 편집 중 공격 입력, 시험 중 F8 사용을 확인한다. `PixelViewport`·`PixelText`·기존 640×360 합성을 공유한다. 편집 격자·선택 윤곽·도움말은 실제 플레이에서 숨긴다.
- **반응성과 수명**은 현재 PC에서 가장 큰 방, 최대 범위 채우기, 도장 연속 배치, 취소 50회, 편집↔시험 20회로 측정한다. 브러시 미리보기는 다음 표시 프레임, 대표 방의 따뜻한 상태에서 시험 진입·복귀는 각각 p95 1초 이내를 초기 목표로 둔다. 첫 진입은 별도 측정한다. 반복 중 카메라·타일맵·GPU 버퍼·이벤트 구독 수가 누적되지 않아야 한다.
- **회귀**는 기존 `Dungeon`·`World`·`Presentation`·`Save`·`Performance` 검사를 재사용한다. 문서 왕복, 명령 되돌리기, 독립 플레이어 입력, 자동 복구와 팀 전달은 새 제작실 검증에 추가한다. 빌드 시험에는 에디터 API 의존 검사와 기존 저장 파일·해금값의 전후 대조를 포함한다. 내장 GPU 실측은 기존 보류 조건을 따른다.
