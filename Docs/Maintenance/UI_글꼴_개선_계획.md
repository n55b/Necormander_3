# 640×360 UI 글꼴 개선 계획

## 작업 전 상태

- 시작·전투 씬은 960×540, 옵션 씬은 800×450, 마을에는 960×540과 800×600 기준의 캔버스가 있다. 실제 화면은 640×360 렌더 타깃에 합성한다. 같은 `fontSize`라도 캔버스 기준과 부모 스케일에 따라 표시 크기가 달라진다.
- `Assets/Scenes`, `Assets/Prefabs`, `Assets/Resources`의 YAML에서 직접 정의된 TMP 텍스트 164개가 `ThinMulmaru SDF`를 참조한다. 자동 크기 조절 8개, 소수점 폰트 크기 4개, 자체 또는 부모 스케일이 1이 아닌 경우 11개를 확인했다. 집계에는 중복 항목이 있으며 프리팹 인스턴스의 오버라이드, 상속과 동적으로 생성되는 텍스트는 후속 Unity 검사에서 추가로 확인한다.
- `ThinMulmaru SDF`와 `ThinMulmaru Mono SDF`의 저장된 아틀라스는 Bilinear로 설정돼 있다. `PixelUiTypography`는 등록된 Canvas의 활성 TMP UI에 런타임 비트맵과 Point 샘플링을 적용하지만, 자동 크기 조절은 TMP에 맡긴다. Canvas 밖의 `TextMeshPro`를 생성하는 엘리트 패턴 라벨에는 별도 경로가 있다.

## 제작 규격

| 용도 | 첫 비교 기준 | 화면 배치 원칙 |
| --- | --- | --- |
| 메뉴·버튼·HUD 라벨·카드 본문 | Galmuri11 Regular 12 논리 px | 줄 간격과 베이스라인을 정수 px에 맞추고, 내용에 맞춰 영역과 여백을 조정한다. |
| 화면 제목·중요 동작·경고 | Galmuri11 Bold 12 논리 px 또는 제목용 정수 배율 | 글꼴 굵기와 실제 표시 크기로 위계를 잡고, 한글·영문 문구가 모두 들어가는지 확인한다. |
| 체력·골드·쿨다운·키 표시·피해 숫자 | 숫자와 보조 기호에 맞는 네이티브 비트맵 | 변하는 자리수가 주변 UI를 밀거나 카드 밖으로 나가지 않도록 정렬한다. 일반·치명타는 지정 크기와 색으로 구분한다. |

Galmuri11 Regular와 Bold는 저장소에 들어 있는 TTF를 우선 비교한다. 두 파일의 문자 맵에서 현재 번역 테이블에 사용된 한글 음절 322개를 확인했다. 12px는 원본 제작 규격이며, 실제 획과 크기는 640×360 캡처에서 확정한다. 나머지 영문·기호와 코드·에셋이 런타임에 만드는 문구도 추출해 커버리지를 검증한다. [Galmuri 제작자 문서 및 라이선스](https://github.com/quiple/galmuri)

## 적용 순서

1. **텍스트 인벤토리 작성**  
   Unity에서 전체 씬과 프리팹의 실제 인스턴스, 비활성 템플릿과 중첩 Canvas를 검사한다. TMP UI, 월드 TMP, 기존 uGUI Text 및 런타임 생성 경로를 찾아 에셋·계층 경로·언어 키·실제 논리 크기·누적 스케일·아틀라스·재질·자동 크기 조절을 기록한다. 번역 외부에서 가져오는 툴팁과 아이템명, 키 표시, 이미지에 그려진 UI 문자도 포함한다.
2. **폰트와 합성 경로 확정**  
   설정 화면의 BGM·SFX·언어 드롭다운, 전투 HUD와 허수아비의 일반·치명타 피해 숫자에서 한글·영문 시안을 비교한다. 사용 문자로 비트맵 TMP 아틀라스를 미리 생성하고 Point 샘플링과 mipmap 비활성화를 확인한다. 획 경계는 아틀라스 알파를 확인해 안티앨리어싱으로 중간 알파가 생기는지 검사한다. TMP 기본 글꼴, 굵은 글씨와 예외 문자의 대체 글꼴도 같은 픽셀 규격에 맞춘다. 현재 크기별 런타임 생성과 전체 라벨 순회는 새 경로의 적용 범위와 동적 UI를 검증한 뒤 걷어낸다.
3. **전체 UI 교체와 640×360 재배치**  
   공통 프리팹부터 적용한다. 각 텍스트를 실제 논리 픽셀 크기로 지정하고, 축소한 부모 스케일은 앵커·컨테이너 크기·정수 여백으로 바꾼다. 고정 텍스트에는 연속 자동 축소를 없애고, 긴 문구는 행 높이·폭·줄바꿈·스크롤로 수용한다. 기존 번역 키, 버튼 이벤트, 프리팹 연결을 사용해 작동 순서와 클릭 영역을 확인한다.
4. **동적·월드 텍스트 교체**  
   드롭다운 복제본, 미니맵 라벨, NPC·보스 패턴 이름, 획득 알림, 회복·피해 숫자, 텍스트 효과를 공통 글꼴 규격에 연결한다. 월드 위치와 연출은 소수점으로 계산하고 표시 위치를 논리 픽셀 격자에 맞춘다. 크기 효과는 검증된 비트맵 크기 단계로 전환하고 외곽선과 그림자는 정수 단위로 적용한다.
5. **남은 참조 정리와 검증 자동화**  
   활성 UI에서 이전 SDF 재질, Bilinear 샘플링, 연속 축소가 들어오는 경로를 다시 확인한다. 참조가 끊긴 프로젝트 전용 글꼴·셰이더·변환 코드는 기존 Legacy 규칙에 따라 보관한다. 인벤토리와 검사 진입점을 작업·검증표에 남긴다.

## 전체 확인 범위와 완료 기준

- StartScene, OptionScene, VillageScene, BattleScene, 보스·엘리트 테스트 씬의 텍스트를 확인한다. 시작·로딩·일시정지·게임오버, 튜토리얼·대사, HUD·미니맵·키 안내, 인벤토리·장비·소환수·상점·보상·증강, 카드·툴팁·키워드 링크, 피해·치명타·회복·습득·보스 경고를 실제로 연다.
- 한글과 영어를 모두 테스트한다. 긴 설명, 숫자 길이 변화, 드롭다운을 열거나 닫은 상태, 마스크와 스크롤, 포커스·선택·비활성 상태, 클릭·호버 위치를 확인한다. 글리프 누락과 의도하지 않은 잘림·겹침이 0건이어야 한다.
- 640×360 원본과 1280×720, 1920×1080, 2560×1440에서 확인한다. 1366×768처럼 정수 배율이 아닌 화면은 기존 전체 화면 채움과 Point 샘플링을 검증한다. 4:3에서는 여백과 입력 좌표를 확인한다.
- 현재 캡처와 같은 씬·언어·UI 상태에서 전후를 비교한다. 논리 프레임의 글리프와 베이스라인, 움직이는 피해 숫자의 프레임별 경계, 모달과 툴팁의 표시·입력 위치를 검사한다. `Presentation`, 인벤토리 UI 검사와 Windows 데모에 새 텍스트 검사를 연결한다.

## 에셋 제작과 검사

- 글꼴은 네이티브 8·10·12·15px 크기와 정수 배율로 적용한다. 12px에는 별도 굵은 비트맵이 있다. `PixelText`는 이 규격을 사용하는 TMP 텍스트만 갱신한다. 뷰가 바뀌어도 내부 크기와 획 정렬은 640×360에서 계산한다.
- 시작·옵션·로딩·상점의 Canvas 배치는 640×360 좌표로 저작한다. 다른 캔버스의 텍스트도 실제 프레임으로 투영한 크기를 기준으로 동일한 비트맵을 사용한다.
- `Tools > UI > Rebuild Pixel Font Atlases`는 런타임 코드와 씬·프리팹·콘텐츠·번역 에셋에서 후보 문자를 추출한다. 생성되는 다섯 아틀라스와 메타데이터가 같은 커밋에 포함돼야 한다. 원본 글꼴은 프로젝트의 Galmuri 2.40.3과 같은 버전을 사용한다. [Galmuri v2.40.3](https://github.com/quiple/galmuri/releases/tag/v2.40.3)
- `pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Typography`는 씬·프리팹 검사 결과를 `pixel-typography.tsv`에 남긴다. `Baseline`은 상점, 화면, 전투, 저장 검증까지 포함한다. 이전 프로젝트 글꼴, 재질과 런타임 변환기는 `Legacy/Rendering/Typography`에 보관한다.
