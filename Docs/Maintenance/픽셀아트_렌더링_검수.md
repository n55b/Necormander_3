# 픽셀아트 제작·렌더링 검수

게임의 논리 프레임은 640×360이다. 기본 카메라에서 월드 한 유닛은 32 논리 픽셀이다. 틀어진 에셋을 고칠 때는 원본 PPU와 함께 부모 배율, 타일 셀 변환, 실제 플레이 카메라의 직교 크기를 확인한다. 플레이어와 카메라는 연속 좌표를 쓰고, 파편은 소수점으로 시뮬레이션한 뒤 마지막 투영에서 격자에 맞춘다.

## 재현과 산출물

- 마을과 시드 907 던전에서 카메라를 0~0.99 논리 픽셀만큼 수직·대각으로 이동시켰다. 월드 전체와 타일 단독 렌더를 비교한 결과 두 씬 모두 타일 내부 노출 0픽셀, 새로 나타난 가로 노란 선 최대 길이 0픽셀이었다. 판정 범위는 이 두 씬의 캡처 경로다.
- `Tools/Invoke-UnityVerification.ps1 -Suite ArtDirection`은 밀도 목록, 밝고 어두운 모션 비교판, 세 가지 조명의 전투 프레임, 발광·안개 마스크와 입자 검사를 만든다.
- `-Suite Baseline -CompareTo <기존 asset-inventory.json> -IncludeWindowsBuild`는 씬·타이포그래피·던전·조작·저장 호환성과 배포 빌드를 검사한다.
- `-Suite RenderBudget`은 Windows D3D11 검사용 플레이어를 만든다. Visual Studio의 x64 C++ 도구로 GPU 타임스탬프 플러그인을 빌드한다. 이 플러그인과 측정용 동작은 검사용 빌드에서만 사용한다.
- 다른 Windows PC에서는 검사용 빌드 폴더 전체와 `Tools/Verification/Invoke-PixelRenderPlayer.ps1`을 복사해 `-Player <PixelBench.exe> -Results <결과폴더>`로 실행한다. Unity 설치가 필요하지 않다.
- GPU가 여러 개인 PC에서는 `-ExpectedGpu "<측정할 GPU의 모델명>"`으로 결과의 장치를 대조할 수 있다. 전달받은 폴더는 같은 스크립트의 `-ReviewOnly -Results <결과폴더> -ExpectedGpu "<모델명>"`으로 다시 판정한다. 네 가지 창 각각의 실제 크기·전체 뷰포트·입력과 일곱 시나리오 각각의 60초 구간·CPU·GPU 표본을 확인한다.
- 프로젝트의 결과 복사본은 `Logs/Verification`에 있다. 시각 기준은 `Combat-Torch.mp4`, `Combat-Ambient.mp4`, `Combat-HeavyFog.mp4`와 `Motion` 폴더의 원본 크기 PNG다. Windows 창별 비교는 `WindowChecks`에 있다. 640×360·1280×720·1920×1080은 내부 이미지를 최근접 확대한 결과와 전체 픽셀이 일치했다. 1366×768에서 일치율은 99.987%였고 화면 네 모서리의 표시와 클릭은 모두 통과했다.

## 전투·보상 개편 후 재검수

RTX 4060 Ti에서 여섯 품질 조합과 시드 907 혼전을 각각 60초 측정했다. 자연 전투의 프레임 p99는 8.40ms, 최악은 17.48ms였다. 일곱 구간 모두 백분위 예산을 통과했으며 분석식 중간 품질에서 단일 42.87ms 프레임이 있었다. 실제 창 네 크기에서 화면 채움과 모서리 클릭도 재확인했다. [검수 보고서](전투_보상_연출과_혼전_성능_검수.md) · [품질별 원본 측정](../../Logs/Verification/CombatPolish/RenderBudget/pixel-render-60.json)

E4의 내장 GPU 실기기 측정과 해당 기기 예산 확정은 사용자 요청에 따라 보류했다. 이 PC에서 사용 가능한 물리 그래픽 장치는 RTX 4060 Ti이며, Windows에 등록된 AMD Radeon(TM) Graphics는 장치 관리자 코드 45(현재 연결되지 않음)다. 별도 Windows PC에서 실행할 파일은 [측정 패키지](../../Builds/PixelReview/Necromander-PixelBench-Windows.zip)에 있다.

## 개편 전 Windows 실측

Unity 6000.0.59f2, D3D11, 1280×720 창, NVIDIA GeForce RTX 4060 Ti, AMD Ryzen 9 9950X3D에서 측정했다. CPU 열은 Unity 프레임 타이밍이며 GPU 열은 렌더 스레드의 D3D11 타임스탬프 구간이다. 프레임 열은 연속 업데이트 사이의 실제 경과 시간이다. 각 품질 조합과 실제 던전 혼전은 60초다.

시드 907 일반 방에서 최대 적 4명이 활동했고 피해 처리 239건을 확인했다. 던전 재입장과 보스 방에서 논리 프레임, 바닥 마스크, 월드 입자 필드는 각각 1개였다. 본마스터는 두 번의 마무리 타격 뒤 보상·클리어에 도달했다.

개발 플레이어의 별도 2초 표본에서 Unity 관리 힙 할당 p95는 여섯 품질 조합 모두 306 B/프레임이었다. 배포용 플레이어에서는 관리 힙 카운터가 검증용 8 KiB 할당을 감지하지 못했다. 해당 빌드의 할당량은 미수집으로 표시한다.

같은 시드에서 개발 플레이어로 혼전만 60초 다시 측정했다. 적 4명, 적중 240회, 23,543프레임에서 경과 시간 p99는 7.11ms, 최악은 첫 표본의 21.11ms였고 관리 힙 할당 p95는 76 B/프레임이었다. 첫 표본은 프로파일러 초기화 구간을 포함한다. 이 실행에서는 배포 측정의 44.67ms 지연이 재현되지 않아 원인을 특정할 수 없었다. 원시 마커와 할당량은 `Logs/Verification/crowd-hitch-trace.json`에 있다. 같은 진단은 `PixelBenchmarkBuild.RunWithProfiler`로 만든 개발 플레이어에서 `-pixelBench <결과.json> -crowdProbe -benchSeconds 60`으로 재현한다.

기준 PC에서 여섯 품질 조합과 혼전이 초안의 백분위 예산을 충족했다. 혼전 최악 프레임은 44.67ms였다. 하한 내장 GPU 실기기 결과는 아직 없다. 측정용 빌드는 `Builds/PixelReview/Measurement`, 별도 저장 영역을 쓰는 게임 빌드는 `Builds/PixelReview/Windows`에 있다.
