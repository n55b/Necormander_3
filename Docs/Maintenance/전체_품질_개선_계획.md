# Necromander 전체 품질 개선 계획

2026-11-20 작업본 기준. 우선순위는 플레이 중 보이는 결함, 제작 중 놓칠 수 있는 손상, 향후 수정 비용 순으로 정했다. 아래 수치는 현재 작업본을 읽어 집계한 값과 직전 격리 검증 결과다. 프레임 시간 목표와 신규 검사는 다음 작업의 제안이다.

2026-11-21에 추가한 [픽셀아트 제작과 렌더링 개선 계획](픽셀아트_제작과_렌더링_계획.md)에 적·환경의 도트 밀도, 텍스트 애니메이션, URP 분위기, GPU 파티클 이관 순서와 완료 조건을 정리했다.

## 실행 순서와 완료 기준

### 1. 실제 플레이 경로와 깨진 참조를 먼저 복구

- 화살 함정의 대기·발사를 전환하고, 궁수 엘리트가 투척하는 순간, 복도 생성과 미니맵 갱신을 각각 재현한다. 원본 그림과 프리팹의 GUID·서브 스프라이트 ID·애니메이션 바인딩을 대조해 유실 참조를 복원한다. Renderer2D의 6건은 설치된 URP 버전의 기본 리소스와 대조한다. 쓰임이 끝난 필드는 호출 경로를 확인해 정리한다.
- `SummonCombatPlaytest`가 중첩 입력 루틴을 끝까지 실행하도록 고치고, 실제 입력 횟수·활성 슬롯·스킬 적중을 검사한다. 허수아비 일반·치명타, 보스 처치도 게임 이벤트에서 시작하는 검사로 보강한다.
- **완료 기준**은 13건 각각의 조치와 근거가 남고, 활성 게임 경로의 미해결 참조가 0건이며, 교대 입력이나 죽음 이벤트를 끊으면 해당 검사가 실패하는 것이다.

### 2. 최종 화면과 월드 이동을 연속 프레임으로 검증

- 시작·옵션·마을·전투·보스·엘리트·맵 제작·방 생성 테스트 씬의 카메라 용도를 목록화한다. 640×360, 1280×720, 1366×768, 1920×1080, 2560×1440과 4:3에서 내부 프레임과 실제 창 출력을 짝지어 남긴다. 화면 모서리 클릭, 조준, 씬 전환, 일시정지와 창 크기 변경도 같은 경로에서 확인한다.
- 16:9 계열은 화면 채움을 우선한다. 1366×768에서는 640픽셀을 똑같은 정수 너비로 1366열에 나눌 수 없어 화면 픽셀 너비가 섞인다. 논리 좌표를 정수로 유지하고, 최종 확대에서 이웃 색이 섞이거나 화면 가장자리에 빈 줄이 생기는지를 따로 검사한다.
- 마을과 고정 시드 던전의 타일 경계·복도·낮은 울타리·큰 나무 앞뒤를 저속으로 상하·대각 이동한다. 노란 선이 나온 프레임의 바닥·데칼·오브젝트·파티클을 차례로 분리해 원인을 좁힌다. Y 정렬은 같은 발 높이, 다중 파츠, 풀 재사용, 방 재진입까지 확인한다.
- 플레이어·적·소환수의 연속·¼·½·1픽셀 표시 모드를 같은 입력으로 비교한다. 파티클 수명·속도·위치는 소수점 계산을 보존하고 최종 표시를 검사한다. 회전 인디케이터와 전조는 각도별 외곽선 두께·끊김·실제 공격 범위를 비교한다.
- **완료 기준**은 16:9 출력 가장자리까지 채움, 표시 위치와 입력 일치, 이동 중 타일 틈과 불필요한 선 0건, 앞뒤 통과 시 의도한 부위 가림, 모드를 바꿔도 같은 물리 경로와 적중 결과다. 노란 선이 재현되지 않으면 사용한 씬·시드·카메라 경로를 기록하고 미재현으로 표시한다.

### 3. 한글 가독성과 아티스트 작업 흐름 완성

- 상점 카드부터 한글·영문 실제 문구로 제목 너비, 줄바꿈, 아이콘과 본문 간격을 조정한다. 시작 메뉴·옵션·인벤토리·보상·툴팁·보스 HUD까지 긴 문구, 선택·비활성 상태와 메뉴 재진입을 확인한다. 글꼴과 재질을 바꾸는 작성 도구·런타임 코드를 추적해 원본 프리팹과 동적 생성 양쪽에 같은 비트맵 크기 규칙을 적용한다.
- 허수아비와 크기가 다른 적에서 치명타·다단히트·소환수 피해를 발생시킨다. 대상별 시작 위치, 연속 숫자의 겹침, 화면 가장자리, 카메라 반동·정수 줌 중 가독성을 본다. 실제 적중 캡처와 의도적으로 떨어뜨린 비교 샘플은 구분해 저장한다.
- Sunyunie Panel의 아트 탭에서 선택한 그림의 실제 편집 원본(Aseprite 또는 SVG), 씬에서 쓰는 출력, 임포트 예외를 바로 열게 한다. 새 파일 등록, 출력 누락·충돌 진단을 지원한다. PNG 시트는 슬라이스·피벗, 네이티브 애니메이션은 프레임·태그·이벤트, 벡터는 9분할·실루엣·1~2색·마스크를 전후 비교한다. 조명·마스크·글리프의 샘플링은 용도별로 검사한다.
- **완료 기준**은 대표 UI에서 한글 낱글자 고립·잘림과 글꼴 복귀 0건, 실제 적중 숫자의 정수 위치·글리프 크기 유지, 그리고 격리 사본에서 한 픽셀 편집→저장→Unity 재시작 후 반영이다. 원본과 출력이 동시에 수정되면 양쪽 편집본을 보존하고 원인을 패널에 표시한다.

### 4. 렉이 발생하는 구간을 Windows에서 측정하고 수정

- 같은 장비·빌드 설정·시드·입력으로 방 최초 입장, 대규모 교전, 소환수 다단히트와 피해 숫자, 보스 전조, 인벤토리·상점을 재현한다. 첫 실행과 준비된 상태를 나누고 프레임 시간 p95·p99·최대, CPU·GPU 시간, GC 할당과 효과 풀 확장을 기록한다. 60fps를 임시 비교 목표로 삼으면 프레임 예산은 16.7ms다.
- 후보는 방 생성·타일 쓰기, 참여자 깊이 샘플링과 재정렬, 텍스트 효과의 메시 재생성, 파티클·피해 숫자의 첫 생성이다. 프로파일러에서 스파이크를 소유한 경로부터 한 가지씩 수정한다. 동일 시드로 다시 측정해 절감량과 화면·판정 결과를 함께 남긴다.
- **완료 기준**은 재현 구간별 가장 느린 프레임의 원인이 설명되고, 같은 조건의 반복 실행에서 p99와 해당 스파이크가 개선되는 것이다. GPU 측정값이 없으면 미측정으로 표시한다.

### 5. 제어 패널과 코드 구조를 정리하고 재발 방지

- 실제 입력으로 선이동→스윙→느린 조향→복귀 순서와 벽 접촉·공격 취소를 검증한다. 보상·옵션·게임오버가 겹친 상태에서 히트스톱과 슬로모션 소유권을 확인한다. 자주 바꾸는 이동·연출 값은 Sunyunie Panel에서 현재 에셋과 단위를 보여 주고, 같은 값을 씬·프리팹·코드 여러 곳에 복제한 경로를 줄인다.
- 맵 생성은 복도 생성·씬 적용·미니맵 반영, 엘리트는 행동 결정·텔레그래프·취소 정리 순서로 책임을 분리한다. 먼저 기존 입력·출력과 직렬화 경계를 고정한다. GUID, 애니메이션 이벤트, 세이브 키와 UnityEvent를 보존하고 기능 단위마다 회귀 검사를 실행한다.
- 실행이 끝난 도구·셰이더는 코드·씬·프리팹·머티리얼·Resources 키·에디터 메뉴 참조를 확인한 뒤 루트 `Legacy`에 텍스트로 보존한다. `ARTIST/LEGACY`에는 매핑이 살아 있는 10개 원본이 있으므로 패널에서 사용처를 식별한다. 활성 문서·주석에는 현재 계약과 단위·호출 시점을 남기고 중복된 과거 지시·결과 기록은 기본 검색에서 제외한다.
- MCP는 로컬 연결, Unity 세션, 대상 프로젝트 경로, 읽기 전용 씬 조회까지 순서대로 확인한다. 패키지 복원에는 검증한 Git 리비전을 사용하고, 격리 검증과 실제 편집 세션은 각각의 상태를 표시한다.
- **완료 기준**은 패널에서 값을 바꾸고 씬 재진입·재실행 후 같은 값이 적용되며, 보관 코드가 컴파일·메뉴·빌드·기본 검색에 나타나지 않는 것이다. 다음 작업자가 작업·검증표 한 행에서 설정 원본, 런타임 적용 코드, 재현 씬, 검사 명령을 찾을 수 있어야 한다.

## 첫 작업 단위

화살 함정 한 종부터 진행한다. 프리팹과 두 애니메이션이 공유하는 유실 GUID 하나를 추적하면 참조 3건, 아티스트 원본 연결, 함정의 대기·발사 화면을 함께 검증할 수 있다. 그다음에는 치명타의 임시 앵커를 실제 적중 검사로 보완하고, 같은 마을 경로를 카메라·타일·Y 정렬의 반복 재현에 사용한다.

## 검토 근거와 재검사 위치

- 기존 검증 명령과 재현 씬은 [작업·검증표](작업_검증.md)에 있다. 에셋 수정 전후에는 `Tools/Invoke-UnityVerification.ps1 -Suite Baseline -CompareTo <수정 전 asset-inventory.json> -IncludeWindowsBuild`로 비교하고, 전체 미해결 목록과 새로 생긴 항목을 각각 확인한다.
- 화면 출력·타일 이동·치명타 샘플은 [화면 회귀 검사](../../Assets/Editor/UI/PresentationRegressionCheck.cs), 실제 입력 후 반응과 합성 연출은 [카메라 연출 검사](../../Assets/Editor/Feedback/CameraImpactPlayModeCheck.cs), 중첩 입력 처리는 [소환수 전투 검사](../../Assets/Editor/Gameplay/SummonCombatPlaytest.cs)에서 확인할 수 있다.
- 아트 원본과 출력 관계는 [아티스트 안내](../../ARTIST/README.md)와 [동기화 구현](../../Assets/Editor/Art/ArtistSourceSync.cs), 효과 측정 조건과 전후 수치는 [벡터 이펙트 개선 계획](벡터_이펙트_개선_계획.md)에 있다.
