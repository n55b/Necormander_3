# 640×360 벡터 이펙트 개선 계획

## 현재 경로와 우선순위

| 대상 | 코드와 리소스 | 변경 계획 |
| --- | --- | --- |
| 캐릭터 발밑 방향 표시 | `EntityDirectionIndicator`, `RotSpriteCache`, `Arrow_Indicator`, 플레이어·적 기본 프리팹 | 1차 전환. 기존 실루엣과 피벗을 기준으로 벡터 도형을 제작한다. 각도별 스프라이트 생성과 직접 이미지 회전을 정리한다. |
| 화면 밖 적 화살표 | `OffscreenEnemyArrowManager`, `ArrowIndicatorSprites`, `GameManager` 프리팹 | 1차 전환. 논리 프레임 경계에 배치하고 방향을 벡터에 전달한다. 기존 풀링, 최대 표시 수, 대상 우선순위, 은신·사망 처리와 정렬을 검사한다. |
| 돌진·사격 레인, 도약·충격파, 보스 전조 | `BossTelegraph`, `BoneMasterTelegraphUtil`, `BossAttackIndicator`, 관련 전조 프리팹 | 2차 전환. 고정 픽셀을 키우는 원·고리와 길이·각도에 따라 변형되는 레인을 공용 도형으로 옮긴다. 원·타원·고리·부채꼴의 채움과 카운트다운을 실제 판정 범위에 맞춘다. |
| 충격선·잔상과 회전하는 VFX 파티클 | `ImpactFeedback`, `FeedbackBurst`, `AmbientOutlinePulse`, 파티클 렌더러와 관련 애니메이션 | 3차 검토. 회전·스케일 변화로 외곽이 흔들리는 선, 호, 파편, 타원만 전환한다. 손으로 저작한 슬래시와 캐릭터 실루엣은 표시 방식까지 검사하고, 변환이 필요한 부분을 명시한다. |

`Player Melee.prefab`은 발밑 로케이터에 64방향 회전 캐시를 사용한다. 이 캐시는 원본 픽셀을 읽고 확대·회전해 방향별 텍스처를 만든다. 화면 밖 화살표는 `SpriteRenderer`를 직접 회전한다. `BossTelegraph`의 원과 고리는 런타임 비트맵이며, 본마스터는 `LineRenderer`와 전조 프리팹도 사용한다. 반딧불과 일부 근접 파티클은 이미 `PixelBillboard`에서 표시 크기와 위치를 정수 픽셀에 맞춘다.

## 렌더링 규격

- 방향·이동·파티클 수명·전조 진행률은 소수점으로 계산한다. 마우스 조준, 적의 마지막 이동 방향, 부모 좌우 반전, 충돌과 피해 판정을 유지하면서 렌더러에 연속 각도를 전달한다. 발밑 표시의 기준점은 캐릭터의 화면상 발 위치와 맞춘다.
- 화살표·원·선·레인처럼 단순한 도형은 셰이더에서 경계를 계산한다. 복잡한 실루엣은 벡터 경로 또는 메시로 저작한다. 벡터 원본에는 외곽선을 굽지 않고 채움과 외곽선을 별도 값으로 받는다. [HLSL 픽셀 위치 기준](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-semantics)
- 640×360 렌더 타깃에서 논리 픽셀 중심을 기준으로 도형의 마스크를 결정한다. 외곽선은 회전·비균등 스케일을 적용한 뒤 화면 공간에서 계산하고, 기본 두께는 1 논리 px부터 비교한다. 비정형 도형에서만 마스크를 이용한 외곽선 후처리를 후보로 둔다. 프레임 전체에 외곽선을 거는 방식은 비용과 정렬을 비교할 때만 검토한다.
- 가장자리의 두께와 안티앨리어싱은 렌더 규격으로 관리한다. 스프라이트의 의도된 페이드와 전조 투명도는 별도로 적용한다. 16:9 채움과 최종 Point 샘플링은 기존 프레임 출력 기준으로 검증한다.

## 구현 순서

1. 씬·프리팹·중첩 오버라이드·애니메이션·스크립트 생성 이펙트를 목록화한다. 에셋 위치, 회전·스케일 경로, 월드 또는 화면 픽셀 단위, 머티리얼, 판정과의 연결을 기록한다. 마을과 전투 씬에서 변경 전 프레임과 첫 등장·반복 등장 비용을 측정한다.
2. 발밑 로케이터와 화면 밖 화살표에 공용 벡터 표시 경로를 적용한다. 방향, 대상 선별, 렌더링을 나누고, `90°`·`180°` 원본 이미지 보정값과 배율을 실제 벡터 피벗 및 논리 px 크기로 옮긴다. 기존 `0.25초` 조준 유지와 화면 밖 표시 개수 같은 동작 설정은 값의 역할과 소유 위치를 분명히 한다.
3. 보스·엘리트·일반 적 전조를 도형별로 옮긴다. 반경과 각도는 실제 히트박스에 사용되는 값과 연결하고, 발동 전 채움·카운터·위험 구역의 의미를 보존한다. 분산된 렌더링 폴백, 텍스처 생성과 인스턴스별 재질 복제를 참조 단위로 줄인다.
4. 타격·대시·파티클 후보를 전후 캡처와 프로파일로 비교한다. 색상·크기·두께·피벗은 프리셋과 인스펙터에서 조정하고, 공통 설정이 필요한 항목을 `Tools > Sunyunie Panel`에 연결한다. 남아 있는 하드코딩은 단위와 역할을 먼저 확인해 공용 규칙 또는 에셋 설정으로 옮긴다.
5. 모든 참조를 대조한 뒤 대체된 코드·셰이더·재질을 `Legacy`에 보관한다. 더 이상 쓰이지 않는 아트 출력은 `ARTIST` 원본과 매니페스트의 연결을 함께 정리한다.

## 완료 기준

- 발밑과 화면 밖 표시를 360° 회전시켜 정면·대각선과 그 사이 각도에서 외곽선이 끊기거나 도형이 뒤집히는지 검사한다. 이동, 정지, 좌우 반전, 카메라 흔들림, 화면 가장자리, 은신과 사망을 재현한다.
- 일반 적 돌진·사격, 엘리트 도약과 충격파, 본마스터의 레인·고리·안전 구역을 확인한다. 전조와 실제 판정의 위치·폭·반경, 예고와 발동 시각, 취소·사망·씬 전환 시 정리를 검증한다.
- 640×360 캡처에서 도형 중심, 대각선 연결, 1px·2px 외곽선, 화면 모서리 잘림을 확인한다. 1280×720, 1920×1080과 비정수 확대 화면, 4:3 출력도 검증한다.
- 많은 적과 전조가 겹치는 장면에서 CPU·GPU 프레임 시간, 드로 콜과 GC 할당을 변경 전후로 기록한다. 반복 표시에서 방향별 텍스처 생성이 사라졌는지 확인한다. 기존 `Presentation`, `Combat`, 보스·엘리트 전조 정리 검사와 Windows 빌드에서 회귀 여부를 확인한다.

## 구현 후 관리 위치

- `PixelVectorShape`과 `PixelVectorShape.shader`가 발밑 표시, 화면 밖 표시, 궁수 화살, 머리 위 공격 게이지, 원·타원·고리·레인·부채꼴을 그린다. 공격 전조는 위험 영역의 안쪽에 경계를 그린다. `BaseHitBox`가 차오름과 수명을 유지하고 각 공격 코드가 피해 범위와 발동을 관리한다.
- `Tools > Sunyunie Panel > 화면·이동 > 벡터 이펙트`에서 표시 크기와 화살표 여백, 외곽선 두께와 색을 조절한다. 개별 적의 발밑 표시 배율과 표시 채움 색은 프리팹에서 편집한다.
- 타격 섬광·파동·파편은 기존 선 도형의 소수점 위치와 회전을 사용하며 표시 폭을 논리 픽셀 단위에 맞춘다. 저작 슬래시와 잔상의 원본 프레임은 90° 단위로 배치한다. 캐릭터 대시 잔상은 그 순간의 캐릭터 프레임을 사용한다. 단색 반딧불과 근접 스파크는 `PixelBillboard`의 픽셀 스냅을 사용한다.
- 대체된 스프라이트 출력·Aseprite 원본과 회전 캐시는 `Legacy/Rendering/VectorEffects`에 있다. 해당 원본은 활성 `ARTIST/manifest.json`에서 제외했다.

## 합성 부하 측정

Unity Editor에서 640×360 카메라에 방향 표시 64개와 전조 24개를 띄우고, 각 경로를 30프레임 준비한 뒤 120프레임을 측정했다. 렌더 갱신은 표시 방향과 레인 회전을 넘기는 스크립트 구간이다.

| 항목 | 기존 비트맵 경로 | 벡터 경로 |
| --- | ---: | ---: |
| 첫 생성 | 55.143 ms | 2.062 ms |
| 렌더 갱신 중앙값 | 0.033 ms | 0.016 ms |
| 에디터 메인 스레드 중앙값 | 0.901 ms | 1.066 ms |
| 드로 콜 중앙값 | 94 | 94 |
| 에디터 전체 프레임 GC 할당 중앙값 | 280,812 B | 429,998 B |

GPU 타이밍은 배치 환경에서 값이 기록되지 않았다. 메인 스레드와 GC 수치에는 검증 에디터의 프레임 작업이 포함된다.
