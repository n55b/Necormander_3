## 실행

프로젝트 루트의 PowerShell에서 실행한다. Unity Hub의 기본 설치 위치를 쓰지 않을 때는 `-UnityEditor`로 실행 파일 경로를 지정한다.

```powershell
pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Baseline
pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Baseline -CompareTo "C:/path/to/asset-inventory.json"
pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Baseline -IncludeWindowsBuild
pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Performance
pwsh -NoProfile -File Tools/Invoke-UnityVerification.ps1 -Suite Dungeon
```

- `Assets`는 Unity 버전과 Windows 프로필, 빌드 씬, GUID·파일 ID·이벤트·타입과 로딩 키 목록을 만든다. `-CompareTo`는 텍스트 차이를 기록하고 새로 해결되지 않는 GUID가 생기면 실패한다. 파일 ID와 이벤트의 의도된 변경은 차이 보고서에서 확인한다.
- `Presentation`은 실제 씬과 회복 HUD를 확인한다. `Dungeon`은 고정 시드의 배치와 실제 씬 적용을 확인한다. `World`는 이 검사에 타일·충돌·미니맵과 실제 화면 검사를 포함한다. `Combat`은 전투 회귀, `Save`는 저장·이어하기·재실행을 확인한다. `Baseline`은 이 검사들을 같은 임시 프로젝트에 모은다.
- `Windows` 또는 `-IncludeWindowsBuild`는 `New Windows Profile.asset`으로 임시 프로젝트의 `Builds/Verification/Necromander.exe`를 빌드한다.
- 콘솔에 표시되는 임시 프로젝트의 `Logs/Verification`에 `verification-summary.txt`, 개별 Unity 로그, 에셋 목록, 차이 보고서와 640×360 화면 캡처가 남는다. 개별 검사 실패 뒤에도 나머지 검사를 실행하고 마지막에 실패 상태를 반환한다.
- 저장 데이터와 PlayerPrefs는 별도의 회사명·제품명을 사용한다. 검증 복사본에서는 Unity MCP 에디터 패키지를 제외해 작업 중인 MCP 세션과 분리한다.

## 요청을 작업으로 옮길 때

1. 증상별로 씬·메뉴 또는 프리팹, 화면 크기·언어·입력과 기대 결과를 적는다.
2. 소유 파일과 영향을 받는 아래 단계의 연결을 찾아 변경 전 결과를 얻는다. 씬·프리팹에 연결된 스크립트나 에셋을 옮길 때는 `.meta`를 함께 옮긴다.
3. 같은 조건으로 확인해 통과·실패·미실행을 구분한다. 실패에는 재현 조건과 로그를, 수동 검증에는 확인한 씬과 화면을 남긴다.
4. 사용이 끝난 도구와 프롬프트 원문은 `Legacy` 경로에 보관한다. 계속 적용되는 내용은 이 표, 기능 안내 또는 코드의 직렬화·좌표 계약에 남긴다.

던전 병합 예산은 `MapGenerationData.asset`에 있고 기본값은 4ms다. 작업을 마친 방에서만 다음 프레임으로 넘길 수 있다. 미니맵의 전투 HUD 여백과 지형 없는 방의 크기, 레이더 간격과 경계 여유는 `Assets/Prefabs/UI/MiniMap.prefab`에서 편집한다. 논리 해상도는 `PixelViewport`가 정의하고 Sunyunie Panel이 그 값을 표시한다.

## 플레이어 조작 재구성 검증

- 프리팹은 기존 `PlayerInput` 콜백과 애니메이션 이벤트를 사용한다. 입력 차단을 풀 때 현재 이동 액션의 값을 읽어 보간과 물리 속도를 초기화한다. 방 이동 중 눌린 평타와 취소된 F 홀드는 해제 후 실행되지 않는다.
- `CombatMovementCheck.RunPlayerControlChecks`에서 방 전환과 F 홀드 취소, 세 물리 간격의 이동 반응, 대시 곡선과 충돌, 공격 애니메이션 조합 3,456건을 확인했다.
- `Presentation`의 마을 검사에서는 실제 프리팹에 키보드·마우스 이벤트를 주입한다. 이동과 방 전환 후 복구, Shift 대시 충전·무적, 대시 이후 평타 홀드 콤보와 버튼 해제, 허수아비 타격을 확인했다.

## 적 AI 상태 전환 검증

- `EnemyAIDecisionCheck.Run`은 일반 돌진 적과 본마스터 두 페이즈의 패턴 에셋을 복제해 현재 상태를 확인한다. 공격 거리 경계와 쿨타임, 본마스터 등장 대기와 회복, 1페이즈 추격 제한, 2페이즈 집행 개시 조건을 검사한다. 원거리 후퇴는 기존 경로 유지와 새 목적지 요청을 선택하는 규칙을 확인한다.
- `EliteTelegraphCleanupCheck.RunBatch`는 실제 돌진 엘리트 패턴 에셋으로 추격, 특수기 우선 발동, 평타 타이머 보존을 확인한다. 도약·충격파 코루틴을 시작하고 공격 취소 시 해당 적이 만든 전조가 제거되는지도 검사한다.
- `BoneMasterCombatCheck.Run`은 기존 카운터와 집행의 성공·실패 규칙을 확인한다. 세 검사는 `Combat`과 `Baseline`에서 실행한다.

## 런 저장 호환성

- 지원 형식은 `Application.persistentDataPath/save_data.json`의 v2다. 기존 JSON 키와 에셋 이름을 사용하며, 소환수는 현재 이름을 우선하고 이전 이름도 해석한다. 두 번째 소환수 강화와 활성 슬롯이 없던 v2에서는 두 값이 0으로 시작한다. 주머니는 유효한 아이템의 사본과 획득 순서를 복원한다.
- 저장 시 임시 파일을 디스크에 반영한 뒤 현재 파일을 교체한다. 직전 정상 저장은 `save_data.json.bak`에 남는다. 손상됐거나 사라진 주 파일은 정상 백업에서 이어할 수 있다. 미지원 버전의 파일은 보존하고, 명시적으로 새 게임을 시작하면 두 파일을 삭제한다. 층 이동 포털은 저장에 실패하면 다시 사용할 수 있다.
- `SaveCompatibilityCheck`는 잠긴 파일, 잘린 JSON, 필수 필드 누락, 백업 복구, 미지원 버전 보존을 검사한다. Play Mode에서 예전 v2로 이어하고, 두 번째 소환수를 강화해 다음 층으로 이동한 뒤 별도 Unity 프로세스에서 새 저장을 이어한다. 진행 중인 런과 환경설정은 검증용 회사·제품명의 폴더에 기록한다.

## 픽셀 글꼴과 메뉴 검증

- 마을의 소환수 선택, 던전 보상, 장비 강화는 `RewardSelectionUI`와 `RewardCard`를 공유한다. 640×360 기준으로 이름은 15px, 설명은 12px 비트맵을 사용한다. 세 시작 소환수의 이름·스킬 문구는 Reward Text Table에, 창 제목과 건너뛰기는 UI Text Table에 있다. 건너뛰기는 112×26px이며 포인터와 키보드 포커스가 같은 테두리를 밝힌다. 눌렀을 때 판과 글자만 1px 내려가고 입력 영역은 고정된다. Presentation 검사가 두 언어의 문구, 포커스와 눌림, 클릭과 키보드 제출 후 재진입을 확인한다. 바닥 소환수의 습득·교체는 `HandSlotSelectionUI.prefab`에서 같은 카드 표면과 글꼴 규격을 쓴다.
- `-Suite Presentation`은 마을 NPC를 통해 한글·영문 카드 세 장을 열어 설명 높이와 글꼴을 확인한다. 건너뛰기, 재진입, 선택으로 장착, 두 슬롯 비교·교체, 카드 한 장의 가운데 정렬과 긴 강화 설명의 휠 스크롤도 확인한다.

- `PixelTypographyCheck.Run`은 프리팹과 씬의 TMP 라벨, 재질, 글리프를 읽는다. 비트맵 아틀라스의 Point 샘플링, mipmap 1레벨, 획 알파 0·255를 검사하고 계층 경로와 크기를 `pixel-typography.tsv`에 남긴다.
- `PresentationRegressionCheck.Run`은 한글·영문 설정 화면과 드롭다운을 연다. 시작 버튼에 다른 SDF 글꼴·재질·크기를 덮어쓴 뒤 12px 비트맵이 복원되는지 옵션 진입 전과 복귀 후에 확인한다. 마을의 주머니, 스킬 설명, 일반·치명타 피해 숫자와 전투 HUD도 캡처한다.
- `DungeonLayoutCheck.Run`은 생성된 상점을 열어 카드가 640×360 프레임에 그려지는지 확인한다. 긴 상품 설명이 마스크 안에서 휠 입력으로 스크롤되고 가격과 구매 버튼 영역을 가리지 않는지 검사한다.

### 전투 플로팅 텍스트

- `Tools > Sunyunie Panel > 피해 숫자`에서 프리셋의 글꼴 크기, 상승·분산 거리, 수명, 페이드 시작점, 파편 수, 섬광 모양과 화면 가장자리 속도선을 조절한다. 플레이 모드에서는 같은 탭에서 플레이어 위에 샘플을 띄울 수 있다. 거리와 글꼴 크기의 단위는 640×360 화면의 논리 픽셀이다.
- 원본은 `Assets/Resources/UI/CombatText.asset`이다. 스타일의 `glyphMotion`은 `글자 모션` 탭의 프리셋 ID이며 `swatch`는 아티스트 팔레트의 좌상단 기준 좌표다. 새 스타일은 `FloatingTextManager.ShowDamage`의 마지막 인자로 ID를 전달해 재생한다. 피해 종류는 `FloatingTextSpawner`에서 선택한다.
- 숫자는 타격 순간의 월드 좌표를 보관한다. `TextFloating`은 프레임마다 화면으로 투영해 정수 좌표에 놓고, 비트맵 셰이더가 글자마다 1픽셀 그림자를 그린다. `CombatTextBurstField`는 장식 최대 24묶음을 메시 하나에 그린다. 화면 가장자리 연출은 가장 높은 우선순위 한 건이 차지한다. UI 모션을 끄면 피해량과 페이드가 남는다.
- `-Suite Presentation`은 마을 허수아비의 일반타·치명타 좌표와 글꼴을 검사한다. 이어서 64개의 서로 다른 피해량, 화면 네 변과 장식 정점의 픽셀 정렬, 모션 끄기, 숫자 끄기, 풀 재사용과 만료를 검사한다. 결과 프레임은 `CombatTextFinisher.png`와 `CombatTextBurst.png`다.

## 20층 연속 광역 전투와 층 전환

- 독립 Windows 검사용 플레이어에서 `Tools/Verification/Invoke-CrowdMatrix.ps1 -Player <PixelBench.exe> -Results <결과폴더> -AreaBurst -FloorCount 20 -Seconds 2 -Runs 1 -MaxAreaFrameMs 16.7`을 실행한다. 격리된 저장 경로와 시드 907을 사용한다. 첫 타격, 반복 타격, 트리거 타격, 64마리 처치와 동시 드롭을 각 층에서 검사한다.
- 격리 프로젝트의 회사명·제품명이 일치하면 이전 검사용 체크포인트를 결과 폴더에 보관하고 새 게임의 기본 소지품으로 시작한다. 매 층 보상 9개를 실제로 줍고 다음 층을 정상 로드한 뒤 골드와 소지품 사본·순서가 그대로 복원됐는지 확인한다. 다음 전투는 다시 1층과 같은 기본 소지품으로 시작한다. 이동은 저장 요청부터 페이드 종료까지 잰다. `travel-N-M`의 `worstVisible`과 `worstCovered`는 화면이 보이는 구간과 완전히 가려진 구간의 최댓값이다. 둘 다 16.7ms 기준에 포함한다.
- 같은 명령에 `-NaturalGc`를 추가하면 층마다 GC를 강제하지 않고 프레임과 점유 힙을 측정한다. 기본 실행은 GC 후 관리 힙과 두 층 이상 지난 방의 약한 참조를 확인한다. 두 실행 모두 층 진입 직후 에이전트, 이전 탐색 메시, 임시 씬, 영속 루트, 메시·재질·텍스처, Unity 할당량을 기록한다. 층별 로그는 디스크로 내보낸 뒤 종료 시 합친다. [측정 결과](전투_보상_연출과_혼전_성능_검수.md)

## 동적 바닥 그림자

- `Tools > Sunyunie Panel`의 월드 분위기 설정에서 바닥 그림자 농도, 기본 방향과 길이를 조절한다. 지면 접점 주변의 짙은 부분과 광원 반대편에 맺히는 실루엣을 분리해 그린다. 화면에 영향을 주는 로컬 광원은 최대 8개를 거리·반경·밝기로 선택한다.
- `Presentation`은 마을 NPC 양옆에 점광원을 놓고 실제 640×360 프레임에서 그림자 마스크의 차이를 검사한다. 양손을 각각 검사할 때는 해당 손의 그림자만 끈 프레임과 비교한다. 마을과 생성 던전에서 현재 스프라이트의 불투명 밑단과 그림자 접점을 대조하고, 동일한 절벽을 그림자 끔·기본광·반대광으로 촬영한다. 기준 장면과 수치는 `Logs/Verification/ShadowReview`에 있다.

## 인게임 조명 패널과 화면 좌표

- F8 패널과 슬라이더는 `LightingDebugPanel`, 세션 조정값은 `LightingPreview`가 소유한다. `WorldAtmosphere`는 URP 2D 글로벌 광원, 월드 하이라이트, 안개와 블룸을 갱신한다. `GroundShadowField`와 `FrameEdgeMist`가 같은 조정값에서 그림자와 외곽 안개를 읽는다.
- `Presentation`의 `LightingPanelCheck`는 실제 마을의 F8 입력과 마우스 클릭으로 패널을 연다. 방향·고도·색·하이라이트, 블룸·안개, 닫고 다시 열기, 장면 기본값 복원을 검사한다. `LightingPanel-Sun.png`와 `LightingPanel-Atmosphere.png`는 640×360 프레임이다.
- 같은 검사에서 플레이어 정보창을 펼친 채 카메라만 움직인 10프레임과 실제 D 키로 걸은 10프레임의 글자 마스크를 비교한다. 보스 착지 시 HUD 그룹별 최대 이동, 사각 외곽 안개의 네 변과 중앙도 확인한다.

## 포탈 소지품과 전투 감속

- 층 이동 연출은 3초다. 배경 틴트가 먼저 들어오고 0.24초부터 현재 몸·손과 소환수의 자세를 겹쳐 넘긴다. 0.42초부터 일행이 떠오르며 주인공, 소환수, 소지품 순으로 빨려 들어간다. `FloorTravel`에서 박자를 조정한다. `Presentation`은 시작 프레임의 투명도, 틴트의 선행, HUD 퇴장과 복구, 흡입 순서를 검사한다. 실제 씬 전환과 도착 준비는 `Tools > Loading > Run Scene Transition Check`에서 확인한다.
- `FloorPortalDust`는 캡처 텍스처의 각 픽셀에 사각형 하나를 할당한다. `PortalSilhouette.shader`는 원래 픽셀을 지우는 시각에 맞춰 같은 색의 가루를 화면 정수 좌표에서 포탈 중심으로 이동시킨다. `Presentation`은 주인공과 소환수 각각 가루를 켜고 끈 프레임을 비교해 몸 바깥에 분리된 픽셀이 있는지 검사한다.
- 방의 마지막 적은 `RoomFinish` 반동과 마지막 일격 효과를 사용한다. 보스는 `BossDeath` 프리셋과 전용 사운드를 사용한다. `FeedbackBurst`의 섬광, 두 겹의 충격파와 파편은 실제 시간으로 재생된다. `CombatPolish`의 방 검사는 일반 방 보상, 본 마스터의 페이즈 전환과 사망, 처치음 중복 여부, 감속과 정상 속도 복귀를 검사한다.
- 일반 방 문은 화면을 페이드하고 암전 중 이동한다. 소지품 행렬은 층 이동 전용이다. `Presentation`은 같은 소지품 세 개로 일반 문을 통과하며 모든 프레임에서 행렬이 없는지, 도착 위치·입력·인벤토리가 정상인지 검사한다. 층 포탈에서는 배우 교차 페이드, 아이템별 출발·도착 페이드와 순서를 검사한다. 밤하늘과 별빛은 `FloorTravelBackdrop.shader`, 아이템 출발 간격과 흡입 속도는 `PortalItemStream`에서 조정한다.
- 원거리 회피는 `Projectile`과 `AttackGraze`, 방의 마지막 일격은 `RoomFinalBlow`가 판정한다. Sunyunie Panel의 카메라 설정에서 감속 시간과 배율을, Feedback Catalog의 103번과 104번에서 호·파동·소리를 조정한다. `Presentation`은 빠른 투사체, 먼 탄, 일반 접촉, 무적 대시와 시간 복구를 검사한다. `ArtDirection`은 실제 방의 적을 처치해 마지막 처치음이 정확히 한 번 발생하고 시체가 사라지기 전에 감속하는지 검사한다.

## 환경 새떼

- `AmbientBirdFlock`은 마을 바닥과 `MapGenerator.SetCurrentRoom`에서 관리한다. `Presentation`은 마을의 3~6마리가 바닥을 쪼다가 플레이어 접근으로 경계·이륙·비행하는지, 그림자가 발에서 분리되고 무리가 정리되는지 검사한다. 시드 907 던전에서는 통행 가능한 타일과 문 앞 제외 영역, 방을 떠났다가 돌아왔을 때 무리의 수명을 확인한다.
- 원본과 태그 계약은 [방울새 편집 안내](../../ARTIST/WORLD/Wildlife/README.md)에 있다. ARTIST 매니페스트에 `requiredTags`가 있는 네이티브 원본은 캔버스 크기와 필수 태그를 유지하며 프레임 수와 박자를 바꿀 수 있다.
- 새의 감지 반경은 3.65, 비행 속도는 초당 7~8.6 월드 단위다. 마을과 던전에서 3.4 단위까지 접근해 첫 움직임이 0.24초 이내인지, 이륙 후 0.25초 구간의 평균 속도가 초당 6.5 단위를 넘는지 검사한다.

## 공용 UI 표면과 문구 연출 검증

- `PresentationRegressionCheck.Run`은 시작 메뉴, 두 언어의 설정과 소환수 선택, 마을 상태창·주머니, 던전 HUD의 실제 장면을 렌더한다. `PixelTypographyCheck.Run`은 씬과 프리팹 전체에서 비트맵 글꼴과 `PixelText` 연결을 검사한다.
- `ArtDirectionPlayModeCheck.Run`은 일반 텍스트 대입으로 들어온 한글 부분 타이핑·색·반복 조합, 포커스 중 재생 유지, 즉시 표시, 일반 문구로 교체, 모션 감소와 풀 재사용을 검사한다.
- `WorkshopPlayModeCheck.Run`은 제작실 첫 화면의 카드 다섯 장과 찾기, 레벨 영역 헤더에 그 영역 탭만 보이는지, 영역 전환 목록, 메뉴로 나갔다 돌아온 첫 화면의 최근 작업을 확인하고 `WorkshopUx/home`을 남긴다. `WorkshopStatusCheck`는 첫 화면 글자의 글리프와 넘침을 본다(최근 항목 이름은 넘침 검사에서 뺀다).
- `WorkshopPlayModeCheck.Run`은 번역 작성 칸에서 단어를 선택해 색과 물결로 감싸고 문장 전체에 타이핑을 적용한다. 원문과 실제 렌더 문구를 비교하며 `WorkshopUx/TextPlayback`에 재생 프레임을 남긴다.
- `InventoryUICheck.RunRuntimeBatch`는 실제 상점의 벡터 구매 버튼을 눌러 판매 완료·중복 결제 방지와 아이템 획득까지 검사한다.
