# Necromander 프로젝트 재구성 계획

현재 플레이 가능한 상태를 기준으로 기능 경계를 정리한 뒤, 검증된 범위부터 옮긴다. 각 작업은 씬, 프리팹, 리소스, 테스트의 연결까지 검토하고 하나의 변경 단위로 마친다.

## 현재 기준선

- `Assets/Scripts`에 C# 259개, `Assets/Editor`에 74개가 있다. 두 디렉터리만 약 6만 7천 줄이다. 씬 파일은 8개, `Assets/Prefabs`에는 프리팹 169개가 있다.
- `MapGenerator.cs` 2,835줄, `PlayerController.cs` 1,073줄, `UIBasedMiniMap.cs` 890줄은 기능 경계를 잡을 때 먼저 살펴볼 파일이다. 미니언·적과 장비 에디터도 각각 여러 작업을 한 창에서 처리한다.
- 카메라와 UI의 논리 해상도는 640×360이다. 마우스, 월드, UI 좌표 변환은 `PixelViewport`에 모았다. 화면 연출이 받는 좌표를 함수 이름과 테스트에 드러내도록 유지한다.
- Aseprite 편집 원본은 루트 `ARTIST`에서 관리한다. 게임에서 참조하는 Unity 출력은 `ARTIST/manifest.json`으로 추적한다. `Legacy`는 실행에서 격리된 기록이며 `ARTIST/LEGACY`에는 현재 씬에서 참조하는 그림도 있다.

## 목표 구조

아래의 경계는 코드 소유권을 잡는 기준이다. 실제 폴더 이동은 각 모듈의 참조와 회귀 검증을 확보한 작업에서 진행한다.

| 영역 | 소유할 책임 | 첫 이동 후보 |
| --- | --- | --- |
| Rendering | 640×360 프레임, 출력 화면비, 카메라·월드·UI 좌표, 글리프 아틀라스, 스프라이트와 파티클의 표시 단위 | `PixelArtUpscaleRig`의 프레임 출력과 좌표 API, `PixelText`, `PixelActorMotion`, 픽셀 셰이더 |
| UI | 입력과 팝업, HUD 표시, 전투 피드백, 툴팁, 현지화 | `TextFloating`, `DashCooldownUI`, `PlayerStateUI`, `CommonTooltipUI`, `FeedbackOverlay` |
| World | 맵 레이아웃과 연결 규칙, 방 배치, 타일 생성·렌더, 포탈과 오브젝트 표시 | `MapGenerator`, `RoomInstance`, `CorridorPainter`, `UIBasedMiniMap`의 맵 데이터 입력 |
| Combat | 공격 및 피해 규칙, 체력과 상태이상, 투사체·히트박스, 입력과 이동 | `PlayerController`, `MeleeCombatController`, `CharacterHealth`, `DamageInfo` |
| Actors & Progression | 적 AI와 소환수, 데이터 레지스트리, 보상·장비·인벤토리, 저장 | 적·소환수 컨트롤러와 AI 설정, `RewardManager`, `InventoryManager` |
| Editor | 아트 동기화·검증, 콘텐츠 편집, 읽기 전용 진단, 배치 검사 | 각 기능의 편집기와 검증을 해당 영역에 연결하고 사용자 입구는 Sunyunie Panel과 기능별 메뉴로 유지 |

게임 규칙은 UI나 픽셀 좌표를 의존하지 않도록 정리한다. 전투에서 발생한 피해와 그 월드 위치를 UI에 전달하면, UI가 Rendering의 좌표 API로 표시한다. World는 맵 연결과 방 상태를 제공하고 미니맵이 이를 표시한다. 씬 시작점과 공용 게임 매니저에서 필요한 연결을 확인할 수 있게 한다.

## 진행 순서

### 1. 작업 전후를 비교할 기준선 만들기

1. 현재 Unity 버전과 Windows 빌드 프로필, 빌드 씬, 프로젝트 설정, 640×360 캡처를 기준선으로 기록한다. 테스트는 제품명을 바꾼 임시 프로젝트에서 실행한다.
2. 씬과 프리팹에서 컴포넌트, GUID와 파일 ID, 중첩 프리팹, UnityEvent, 애니메이션 이벤트, `SerializeReference`의 타입을 수집한다. `Resources.Load`, Addressables, 저장 데이터의 문자열 키도 목록에 담는다.
3. 기존 Console 오류를 기록하고 새 오류와 비교한다. Visual Scripting의 `UnitOptions.db`에는 과거 타입 이름이 남아 있으므로, 연결된 그래프를 먼저 확인하고 재생성할 수 있는지 검증한다. 화면 차이는 원인과 기대 결과를 확인할 수 있게 캡처를 남긴다.
4. 요청을 변경 단위별로 기록한다. 각 항목에는 사용자가 관찰한 증상, 소유 코드, 영향받는 씬·에셋, 재현 조건, 통과 결과를 남긴다. 예를 들어 피해 숫자는 위치, 글리프 필터, 애니메이션 중 크기, 일반·치명타, 다중 해상도를 각각 확인한다.

### 2. 작동 경로와 보관 경로를 찾기 쉽게 만들기

1. `AGENTS.md`에는 기능별 코드와 검증의 첫 진입점만 둔다. 기능 폴더에서는 어떤 데이터가 들어오고 어느 컴포넌트가 씬·프리팹에 붙는지 짧게 기록한다. 범위별 탐색에서 벤더 폴더와 단순 생성 결과도 건너뛸 수 있게 한다.
2. 현재 쓰는 제작 도구와 읽기 전용 검사를 구분한다. 같은 기능을 쓰더라도 에셋을 덮어쓰는 초기 마이그레이션은 활성 검증 메뉴에서 분리한다.
3. 호출, 직렬화 참조, 에디터 자동 실행, 배치 CLI, 리소스 키까지 확인한 뒤 사용이 끝난 구현을 Unity 탐색 경로 밖의 `Legacy`로 옮기고 텍스트로 보존한다. 정상 검색에서는 제외한다. 실행할 수 있는 소스가 보관 폴더에 새로 들어오는지와 Unity에 옛 메뉴가 등록되는지를 검증한다.
4. 과거 프롬프트와 날짜별 점검 일지는 `Legacy/History`에 모은다. 계속 적용되는 의도는 현재 사용 안내에 옮긴다. 과거 기능명과 날짜가 들어간 주석은 화면 좌표, 저장 키, enum 값, 초기화 순서처럼 현재 코드에 필요한 설명으로 바꾼다.

### 3. 렌더링과 UI부터 작은 기능 단위로 이동하기

1. 프레임 제작과 화면 배치, 좌표 변환, 표현용 카메라 보정을 분리한다. Game View의 크기를 직접 쓰는 곳과 640×360 좌표를 쓰는 곳을 확인한다. 좌표 API는 월드·논리 프레임·실제 화면·캔버스 이름을 구분한다.
2. 피해 숫자, 대시 칸, 회복·습득 아이콘, 툴팁이 공통 좌표를 쓰는 시나리오를 한 번에 검증한다. 폰트 크기와 카메라 흔들림은 물리와 입력으로 전파되지 않도록 연결을 점검한다.
3. 에셋 설정은 `ARTIST`, 임포트 정책, 논리 화면 설정의 관계를 문서와 테스트에서 연결한다. 기존 GUID, 스프라이트 파일 ID, PPU, 피벗, 9슬라이스, 클립 이벤트를 기준선과 비교한다.

### 4. 월드 생성과 표시 분리하기

1. `MapGenerator`를 먼저 읽고 입력 데이터, 시드에 따른 방 배치 결과, 타일 및 오브젝트 적용, 충돌 준비, 런타임 방 상태의 경계를 정한다.
2. 방 배치의 계산 결과를 고정 시드로 검증한다. 실제 Unity 씬에서는 결과를 적용한 후 타일 수, 색과 뒤집기, 오브젝트 수, 포탈 연결, 충돌·이동 가능 영역과 미니맵을 확인한다.
3. 상점, 튜토리얼, 일반 던전, 보스방을 대표 시드와 씬에서 연다. 방을 이동하거나 철수할 때 이전 타일과 임시 오브젝트가 정리되는지 확인한다.

### 5. 전투·AI·성장 영역을 단계별로 옮기기

1. 플레이어 입력, 이동, 공격 시작, 명중·피해, 피드백을 분리하고 실제 호출 경로를 남긴다. 허수아비와 이동하는 적을 대상으로 일반·치명타·가드·대시·소환수 효과를 검사한다.
2. 적 AI의 순수한 판단과 Unity 컴포넌트 호출을 나누고, 일반 적·엘리트·보스에서 상태 전환과 기존 에셋을 확인한다.
3. 인벤토리, 장비·소환수 레지스트리, 성장 상태의 저장 경계를 정리한다. 격리 복사본에서 기존 세이브의 읽기·저장·재진입을 확인하고, 세이브에 기록된 키와 에셋 식별자의 호환성을 검증한다.
4. 기능 경계가 안정된 영역부터 어셈블리 정의를 후보로 검토한다. 에디터 코드와 런타임 코드를 나누고 순환 참조를 제거한다. 직렬화된 타입 이름이나 UnityEvent, 리플렉션과 배치 진입점에 영향이 있는 경우 호환 이관을 먼저 검증한다.

## 변경 완료 기준

| 검증 영역 | 확인할 내용 |
| --- | --- |
| 화면 출력 | 내부 타깃이 640×360 Point이며 1280×720, 1366×768, 1920×1080에서 화면을 채운다. 1280×960에서 여백과 입력 위치가 맞는다. |
| 픽셀 표현 | 마을과 던전에서 카메라를 이동·흔들었을 때 타일 경계와 오브젝트가 안정적이다. 파티클 시뮬레이션은 소수점을 유지하고 사각형 표시를 정수 픽셀로 확인한다. 한글·영문 UI, 일반·치명타 피해 글자, 애니메이션 중 크기와 위치를 본다. |
| 입력과 UI | 버튼 클릭, 툴팁, 키워드 링크, 마우스 조준, 대시 표시, 회복 도착을 같은 위치에서 확인한다. |
| 게임 흐름 | 시작·옵션·마을·전투가 전환되며 튜토리얼·일반 방·상점·보스 흐름이 정상이다. 저장과 로딩은 격리 데이터로 확인한다. |
| 자산과 빌드 | 누락된 직렬화 참조가 늘지 않는다. 대표 PNG와 Aseprite 저장을 Unity가 반영한다. 원래 Windows 빌드 프로필로 패키징하고 실행한다. |
| 작업 추적 | 사용자 요청의 각 항목을 실제 변경과 검증 결과에 연결한다. 통과하지 못한 씬이나 시나리오는 이름과 원인을 기록한다. |

## 작업 현황

기준선 명령, 기능별 소유 파일과 재현 조건은 [작업·검증표](작업_검증.md)에서 관리한다.

1. 렌더링 진입점·프레임 출력·좌표·글꼴·월드 카메라 정렬을 분리했다. 씬에서 사용하는 컴포넌트는 기존 GUID를 따라 옮겼다.
2. 타일 복사·삭제와 방 연결 규칙을 `MapGenerator`와 `RoomInstance`에서 분리했다. 고정 방 배치 검사와 실제 배틀 씬 검사에 연결했다.
3. 피해 증폭·치명타·방어력 계산을 `DamageRules`로 옮겼다. `CharacterHealth`가 피격 이벤트, 보호막, 상태이상, 체력과 사망 순서를 담당한다.
4. 참조가 끊긴 이전 상태 에셋과 플레이어 이동 백업을 Legacy로 옮겼다. 빌드 목록의 경로가 사라진 씬 두 개를 정리하고, 목록 안의 씬 파일 존재 여부를 검사한다.
5. 전투 HUD의 지형을 메시로 묶고 마커 좌표 계산에 방 지형 범위를 재사용한다. 던전 병합 중 고정 대기는 프레임 예산으로 바꿨다. 성능 전후와 조절 위치는 작업·검증표에서 확인한다.
6. 격자형 던전의 시드·방 배치·문 계획을 씬 적용에서 분리했다. 튜토리얼, 일반 던전, 엘리트 아레나, 보스 층을 고정 시드로 생성하는 Play Mode 검증을 추가했다. 일반 던전은 씬을 다시 열 때와 현재 씬에서 다시 생성할 때 같은 결과를 확인한다.
7. 플레이어의 입력 콜백, 이동·물리, 상호작용을 나눴다. 가속·감속·방향 전환은 `PlayerLocomotion`이 계산한다. `MeleeCombatController.PlayerAttack.cs`는 공격 시작 조건과 히트박스 생성을 구분한다. 프리팹 콜백, 에디터 설정 필드와 클립 이벤트의 기존 이름을 유지했다.
8. 일반 적의 대기·추격·후퇴·공격, 돌진 엘리트의 특수기 우선순위, 본마스터 두 페이즈의 전환 규칙을 `EnemyAIDecisions`로 옮겼다. 기존 패턴이 Unity의 내비게이션과 공격 코루틴을 실행한다. 본마스터 2페이즈의 교전 반경 밖 추격에는 종료 시각이 없으므로 실행에 연결되지 않은 추격 제한 설정을 정리했다.
9. 런의 스냅샷과 복원 순서를 `GameManager.RunProgress`로 분리하고 저장된 콘텐츠 이름은 `GrowthRegistrySO`에서 해석한다. v2 형식으로 저장하며, 임시 파일을 반영한 뒤 기존 체크포인트를 교체하고 직전 정상 파일을 백업한다. `Save` 검증은 이전 v2의 이어하기와 다음 층 체크포인트의 프로세스 재실행을 다룬다.
10. 다음 단계는 어셈블리 의존성 검토다. 에디터 전용 도구와 의존성이 적은 런타임 영역부터 후보를 고르고, 기존 직렬화와 초기화 경로가 유지되는지 확인한다.

Visual Scripting의 노드 데이터베이스는 검증 복사본에서 재생성되고, 그 상태로 화면 및 전투 회귀 검사를 통과했다. 저장소의 생성 캐시는 그래프 편집 사용 범위를 확인할 때 함께 정리한다.
