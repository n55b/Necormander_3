# DATA · 인게임 제작 원본

Unity에서 **Tools > Sunyunie Panel > 제작실** 또는 **Tools > Level Workshop > Open in Play Mode**를 연다. 기본 작업 공간에서 변경할 문서를 열고 Game 뷰 안에서 **Ctrl+S** 또는 해당 화면의 저장 버튼을 누른다. **내 작업 > 모두 저장**과 **Ctrl+Shift+S**는 열린 문서의 변경을 저장한다. 방을 시험할 때는 **F6**, 일반 게임에 반영됐는지 확인할 때는 제작실을 나와 새로 방에 진입한다.

## 제작 화면과 반영 시점

| 바꾸려는 내용 | 제작실에서 열 곳 | 기록되는 원본과 반영 시점 |
|---|---|---|
| 기존 방의 벽·소품·출구 | 내 작업 → 게임 방 편집 → 게임 원본 편집 | `WORLD/ROOMS/<id>/`에 바뀐 셀·개체가 저장된다. 일반 던전의 다음 생성부터 적용된다. |
| 방 전투 | 방 → 전투 설정 | 웨이브마다 `ENCOUNTER/WAVES/<순번>.json`으로 나뉜다. 웨이브 번호는 전투에서 실제 등장하는 순서다. 방 클리어 보상은 방 종류가 정하므로 방 문서에 없다. 옛 `ENCOUNTER/reward.json`은 읽을 때 무시하고 다음 저장 때 지운다. |
| 신규 방 | 새 방 만들기 → 저장 → 던전 등록 | 원본과 별도 ID로 저장한다. 등록 시 `WORLD/POOLS/<기반 방>/<새 방>.json`이 추가된다. |
| 층·튜토리얼·마을 | 게임 설정 → 무대 선택 | `WORLD/FLOORS`는 배치, 웨이브, 순서, 시드별 방 연결을 구분한다. `WORLD/VILLAGES/main`은 NPC, 인사말, 조명을 나눈다. 시험용 시드는 개인 작업 공간에 저장한다. |
| 조작·밸런스·연출 | 플레이어 수치 또는 내 작업 → 콘텐츠 수치 | `BALANCE/PLAYER`는 이동과 근접 공격, 다른 콘텐츠는 에셋 GUID 단위로 기록한다. 기존 에셋의 수치·문자열·열거값을 수정하고 프로젝트 데이터 참조는 호환되는 항목에서 선택한다. 세이브 옛 이름·소환수 종류·애니메이터 상태 이름·패턴 문구·실행 상태 필드는 "읽기 전용"으로 보이고 저장·빌드 검증이 거부한다. 아이템 효과·장비 패시브·대기 효과·창별 소리·연출·적 군집·층 보스 목록의 원소는 숨김 키(`@<키>`)로 기록하므로 순서가 바뀌어도 값이 같은 원소를 따라간다. 키가 비었거나 겹친 에셋은 Unity에서 열어 다시 저장한다. 플레이어 설정은 다음 생성부터, 참조 에셋의 수치는 게임이 그 값을 다시 읽을 때 적용된다. 에셋별로 **프리셋**을 만들고 불러와 다른 조합을 시험할 수 있다. |
| 대사·번역 | 내 작업 → 대사 편집 또는 UI·보상 번역 | `DIALOGUE/LINES/<대화>/<언어>`는 줄과 순서를 나눈다. `LOCALIZATION/STRINGS/<테이블>/<언어>/<키>.json`은 한 언어의 한 문구다. 다음 대화·번역 조회부터 읽힌다. |
| 그림·기준 팔레트 | 내 작업 → 아트 원본 | 현재 그림과 가져올 Aseprite의 첫 프레임을 나란히 비교한다. 기준 팔레트의 색 번호와 RGB를 수정할 수 있다. 저장은 기존 `ARTIST` 원본을 갱신한다. Unity 동기화가 기존 출력과 GUID·슬라이스·애니메이션 연결을 유지한다. `Library/WorkshopArt`에 이전 원본을 보관한다. |
| 팀 공유 묶음 | 공유 → 묶음의 개정 비교 | 방·층·마을의 두 값을 비교하고 새 개인 작업 공간으로 열거나 기본 작업 공간에서 선택한 내용을 DATA에 적용한다. |

프로젝트에는 기존 게임에서 가져온 **방 24개, 조작 수치 5개, 한국어 대화 10묶음 36줄, UI·보상 번역 586개**가 들어 있다. 방의 기본 지형과 리소스 참조는 원본 프리팹이 제공한다. 방별 프로젝트 데이터가 해당 프리팹 위에 편집분을 적용한다. 개인 초안, 실행 세이브, 즐겨찾기와 현재 프로젝트 경로는 팀 커밋에서 제외한다.

## 원본을 찾는 기준

| 원본 | 안정 참조와 게임 진입점 | 제작실에서 하는 일 |
|---|---|---|
| 방 프리팹, 카탈로그, 타일, 출구, 적 클러스터 | 프리팹·타일 GUID와 기반 개정, `DungeonLayoutPlanner` → `MapGenerator` → `RoomInstance` | 지도에서 고치고 **비교**로 저장 기준과 현재 방을 같은 시야에서 본다. 배치물을 선택하면 위치 수치를 열 수 있다. |
| 기존 밸런스·보상·게임 연출 | `Assets/SOData` 에셋 79개와 지정된 Resources 프로필, `ProjectParameterBindings` → 기존 시스템의 같은 ScriptableObject | **콘텐츠 수치**에서 영역·에셋·속성을 검색한다. 플레이 중 적용된 임시 값은 모드를 끝낼 때 원래 에셋에 복원한다. |
| 아이템·장비·메인 소환수·보물 | `CATALOG/VARIANTS/<ID>/definition.json`의 원본 GUID, 개별 `parameters.json` | 기존 항목에서 **복제해 만들기**로 새 콘텐츠를 만든다. 원본이 속한 성장·상점 목록에 추가되고 새 세이브 키를 받는다. 기존 세이브의 이름 해석은 `GrowthRegistrySO`가 유지한다. 적·스킬 등 다른 밸런스 콘텐츠의 복제본은 사용하는 데이터의 참조 필드에서 연결한다. |
| 한국어·영어 UI와 보상 이름, 대사 | Unity 테이블 GUID·숫자 키, 대화 ID·언어·줄 ID | 기존 키를 유지하며 번역을 수정하고 새 키와 본문을 함께 만들 수 있다. 새 대화, 등장인물, 화자와 줄 순서는 대사 편집에서 만든다. |
| 그림·애니메이션·팔레트 | `ARTIST/manifest.json`의 Aseprite 연결 577개, 별도 벡터 매니페스트 | 원본 검색·교체·첫 프레임 비교·기준색 수정이 가능하다. Aseprite 레이어와 프레임 제작, SVG 원본 편집은 기존 아티스트 워크플로를 따른다. |
| 장면·프리팹 배선·코드·오디오 및 폰트 파일 | Unity GUID, 임포터, Resources와 씬 참조 | Unity가 읽는 실물과 제작 데이터의 경계를 유지한다. 사운드 큐와 텍스트 모션의 수치는 콘텐츠 수치에서 수정한다. |

## 두 사람이 같은 방을 편집할 때

1. 각자 자신의 체크아웃에서 같은 **게임 원본 편집** 항목을 연다. 지형 담당자는 원하는 타일을 수정하고 Ctrl+S를 누른다. 전투 담당자는 전투 설정에서 웨이브를 추가하거나 군집을 바꾸고 저장한다.
2. 지형 커밋에는 해당 레이어의 16×16 청크가, 전투 커밋에는 웨이브 파일이 들어간다. 각자 변경을 커밋하고 일반 Git pull·push 흐름으로 합친다. 새 체크아웃에서 같은 방을 생성하면 두 변경을 함께 읽는다.
3. 같은 파일이 Git 병합 충돌로 남으면 **공유 → Git 충돌 확인**에서 기준과 양쪽 값을 확인한다. 해결 저장은 선택한 파일만 스테이징한다. 최종 커밋과 푸시는 담당자가 수행한다.
4. 저장하다 중단되면 다음 문서 접근에서 `Library/ProjectContent`의 기록으로 미완료 교체를 끝낸다. 복구 중 제3자가 바꾼 파일은 해당 경로를 표시하고 중단한다.

Windows 제작판은 **프로젝트 연결**에서 체크아웃을 선택할 수 있다. 일반 배포판은 빌드에 담긴 `StreamingAssets/DATA`를 읽는다. 아래 표는 제작 도구 전체 이관의 설계와 인수 조건이다. 검증 결과는 [작업·검증표](../Docs/Maintenance/작업_검증.md)를 따른다.

| 단계 | 이번 검수에서 확인한 내용 |
|---|---|
| 원본 기준선 | 실제 Unity 에셋에서 방·번역·플레이어 기본값을 추출했다. 한국어 대사는 보관 CSV의 화자·본문·순서와 전 줄을 대조했다. |

| 동시 편집과 복구 | 두 실제 Git 체크아웃의 분리 커밋·푸시·병합, 같은 셀 선택, 한 청크의 서로 다른 셀 병합, 무변경 저장, 쓰기 도중 Unity 강제 종료를 재현했다. |
| 월드 | 새 방의 후보 등록과 일반 던전 등장, 마을에서 저장한 인사말과 일반 마을 재진입, 기존 튜토리얼 경로·방 연결을 검사했다. |
| 제작실 데이터 | 플레이어·층·아이템 변경, 새 아이템의 세이브 키, 게임 데이터 간 참조, 대사·영어 문구, 팔레트 색의 미리보기와 원본 저장을 검사했다. |
| 팀 인수 | 검수 도구가 지형 담당과 전투 담당의 작업 경로를 각각 수행했다. 실제 팀원의 첫 방 편집 소요 시간과 탐색 중 막히는 지점은 사용자 관찰 항목이다. |

## 저장 버튼의 계약

1. Game 뷰에서 **Ctrl+S**와 **프로젝트에 저장**은 같은 명령을 실행한다. 현재 편집 문서와 그 문서에 속한 변경분을 저장한다. 다른 탭의 미저장 문서는 표시를 유지하고 **모두 저장**은 별도로 제공한다. 필드에 입력 중인 숫자·문자, 마지막 브러시 획까지 반영한다. 제작실에 입력 포커스가 있을 때만 Unity의 씬 저장 단축키와 중복 실행되지 않도록 처리한다.
2. 슬라이더나 브러시는 화면에 즉시 미리보기를 보여준다. 저장하면 저장소 루트 `DATA/`에 기록하고 **무엇이 저장됐고 언제 게임에 적용되는지** 표시한다. 예를 들어 조명은 현재 화면, 질주 배율은 현재 시험 플레이어, 방 구조와 웨이브는 다음 방 생성부터 적용한다. 전투 중인 방을 저장 때문에 재생성하지 않는다.
3. 기존 방을 고치면 같은 방을 쓰는 일반 플레이에 적용한다. 새 방은 ID를 발급하고 게임이 읽을 수 있는 콘텐츠로 저장한다. **이 층의 방 후보에 추가**를 선택하면 해당 풀에 전용 연결 파일을 만든다. 화면에는 ‘시험 전용’과 ‘등장하는 층’을 구분해 표시한다. 개인용 시험 시드도 명시적으로 선택했을 때만 정식 생성 규칙에 반영한다.
4. Unity 플레이 모드는 현재 프로젝트를 자동으로 연결한다. Windows 제작판은 처음에 작업할 체크아웃을 선택하고 프로젝트 식별자와 데이터 형식을 확인한다. 체크아웃이 없는 팀원은 기존 로컬 작업 공간과 공유 묶음을 계속 쓸 수 있다. 화면 머리글에 **프로젝트 저장** 또는 **로컬 초안**과 대상 경로를 표시한다. 일반 배포 게임은 빌드에 포함된 데이터만 읽는다. 커밋과 푸시는 팀원이 검토 후 수행한다.

## 무엇을 한 파일에 담을지

디렉터리는 작업자가 찾는 영역을 따르고 파일 경계는 두 사람이 독립적으로 맡을 수 있는 최소 작업 단위를 따른다. 표시명은 바꿀 수 있고 참조에는 바뀌지 않는 ID를 쓴다. **같은 개체를 고쳐도 서로 다른 작업이면 다른 파일이 바뀌는 것**이 기준이다.

| 루트 DATA 아래 경로 예시 | 파일 경계와 작업 예 |
|---|---|
| `WORLD/ROOMS/<room-id>/` | `room.json`은 이름·기반 틀, `TILES/<layer>/<cx>_<cy>.json`은 타일 레이어별 공간 청크, `OBJECTS/<id>.json`은 배치물 한 개, `EXITS/<id>.json`은 출구 한 개. 청크는 16×16셀로 시작해 실제 방에서 Git diff 크기와 편집 속도를 측정한다. 타일 회전·색의 참조도 방 전체에 재번호를 매기는 스타일 배열에서 분리한다. |
| `WORLD/ROOMS/<room-id>/ENCOUNTER/` | 웨이브별 파일을 둔다. 같은 방에서 벽을 칠하고 마지막 웨이브를 바꾸면 서로 다른 경로만 바뀐다. |
| `WORLD/FLOORS/<id>/`, `WORLD/POOLS/<id>/` | 층 생성 규칙과 방 후보·가중치 연결을 나눈다. 두 사람이 각자 새 방을 등록하면 각 방 ID의 연결 파일만 추가된다. 튜토리얼처럼 순서에 의미가 있는 목록은 항목 ID와 순서를 보존한다. |
| `BALANCE/` | 플레이어는 이동·공격·대시 등 기능별, 적·펫·스킬·아이템·장비는 콘텐츠 ID와 편집 책임별로 분리한다. 예를 들어 허수아비의 피격 반응을 고쳐도 플레이어 공격 파일은 그대로다. |
| `PRESENTATION/`, `UI/`, `AUDIO/` | 방·지역별 조명과 안개, 카메라 반응, 파티클·타격 프리셋, HUD 패널과 글자 모션, 사운드 큐를 각각 독립적으로 편집한다. |
| `WORLD/VILLAGES/`, `DIALOGUE/`, `LOCALIZATION/` | NPC 배치·대화·번역은 개별 ID로 연결한다. 같은 NPC의 위치와 한국어 대사를 동시에 수정할 수 있다. |
| `ART/` 및 기타 제작 원본 | 기존 `ARTIST` 원본, 팔레트, SVG, 오디오·폰트의 참조와 라이선스를 목록화한다. 원본도 옮길 때는 종류별로 원본 경로·매니페스트·Unity 출력의 연결을 한 번에 전환한다. 바이너리 충돌은 원본 단위의 중복 편집 경고와 별도 버전 비교로 처리한다. |

팀이 만드는 콘텐츠의 기본 원본은 `DATA/`다. Unity가 요구하는 씬·임포트 출력과 실행 코드는 엔진 측에 두고 안정 ID로 연결한다. 사용자 진행 세이브, 자동 복구 초안, 잠금, 미리보기 썸네일과 생성 캐시는 개인 저장소에 둔다. 콘텐츠 목록은 개별 파일에서 생성한다. 저장할 때마다 전원이 함께 수정하게 되는 전역 매니페스트를 만들지 않는다.

## 충돌과 데이터 손실을 줄이는 방법

- **Git에서 읽히는 변경.** UTF-8·LF·일정한 들여쓰기와 숫자 표기를 사용한다. 순서에 의미가 없는 항목만 정렬한다. 수정 시각과 작업자 이름을 콘텐츠 본문에 쓰지 않는다. 값을 바꾸지 않고 저장하면 파일 쓰기와 Git diff가 모두 0이어야 한다.
- **덮어쓰기 감지.** 문서를 열 때 파일별 기준 내용과 해시를 기억한다. 저장 직전 변경된 파일만 다시 대조한다. 다른 사람이 pull로 같은 파일을 바꿨으면 기준본·내 편집·현재 디스크본을 비교한다. 서로 다른 필드나 타일 셀은 합치고 같은 값을 다르게 고친 경우에만 선택을 요청한다. 삭제 대 수정, 동일 웨이브의 서로 다른 순서 변경도 보여준다. 선택 전까지 내 초안을 보관한다.
- **Git 자체의 충돌.** 분할만으로 텍스트 충돌을 전부 없앨 수는 없다. 이미 병합 충돌에 들어간 체크아웃은 Git의 공통 조상과 양쪽 버전을 읽어 지도 셀·속성 단위로 비교한다. 제작실에서는 결과 미리보기와 해결 파일 저장까지 제공한다. 자동으로 커밋하거나 푸시하지 않는다.
- **여러 파일을 바꾸는 저장.** 방과 출구 연결처럼 함께 성립해야 하는 변경은 한 묶음으로 검증한다. 관련 경로를 일정한 순서로 잠그고 기준 해시를 재확인한 뒤 임시 파일·복구 기록·원자적 파일 교체를 사용한다. 전체 묶음이 완성된 뒤 게임의 활성 데이터 버전을 교체한다. 중간 종료, 디스크 부족, 읽기 전용 경로, 열린 문서에 대한 외부 수정 시에는 마지막 정상본과 작업 초안을 복구할 수 있어야 한다.
- **잘못된 콘텐츠 격리.** 저장 전에 스키마 버전, ID 중복, 사라진 참조, 값 범위, 방 출입구·스폰 위치·연결 관계를 검사한다. 오류는 제작실의 해당 셀이나 필드로 연결한다. 삭제 전에는 이 방·아이템을 쓰는 곳을 보여준다. 빌드는 미해결 충돌이나 누락 참조를 파일·필드와 함께 보고한다.

## 구현 순서와 통과 기준

| 단계 | 구현 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 원본 조사와 기준선 | 씬·프리팹·SO·`Resources.Load`·`ARTIST`·로컬 제작실에 대해 원본, 읽는 곳, 참조 키, 사용자가 편집할 화면을 목록화한다. 기존 플레이어 세이브에 기록된 아이템·소환수 이름도 ID 별칭에 매핑한다. | 기존 방, 이전 형식의 방·팀 공유본, 실제 세이브를 준비하고 이관 전 플레이 결과를 기록한다. |
| 2. 작게 끝까지 연결 | 방 하나의 타일, 웨이브, 플레이어 질주 배율을 먼저 이관한다. Game 뷰에 수치 편집기를 두고 미리보기·저장·다시 읽기를 연결한다. 프로젝트 원본을 읽는 공통 로더와 빌드용 데이터 생성기를 만든다. 빌드 시 필요한 프리팹·타일·머티리얼도 참조로 포함한다. | Ctrl+S와 버튼이 같은 파일을 만든다. Play 종료·Unity 재시작·일반 새 게임·새 Windows 빌드에서 결과가 같다. 프로젝트 원본에 변화가 없는 재빌드는 동일한 콘텐츠를 만든다. |
| 3. 협업과 복구 | 파일 분할, 부분 저장, 외부 변경 감지, 3자 비교, 다중 파일 복구를 완성한다. 기존 방 잠금과 공유본 개정 비교를 재사용한다. | 두 체크아웃에서 같은 방의 지형·전투 웨이브를 각각 커밋하고 로컬 시험 저장소에 push·pull한 뒤 양쪽 결과를 함께 플레이한다. 같은 셀 충돌과 저장 도중 강제 종료도 재현해 두 사람의 편집을 복구한다. |
| 4. 월드 전체 이관 | 모든 방·풀·층·튜토리얼·마을·NPC에 공통 로더를 적용한다. 기존 방과 `.levelpack`은 변환 미리보기와 일괄 가져오기를 제공한다. | 동일 시드의 방 구성·출구·충돌을 비교하고 기존 세이브로 층을 이동한다. 새 방을 인게임에서 등록해 일반 던전에서 실제 등장시키고 프리팹 수동 등록을 없앤다. |
| 5. 제작 도구를 Game 뷰로 통합 | 플레이어·적·아이템·소환수·스킬, 카메라·피드백·조명·안개·파티클, HUD·텍스트, 대사·현지화·사운드 순으로 편집기를 붙인다. Sunyunie Panel은 진입점이 되고 원본을 직접 고치던 Inspector 경로는 영역별로 퇴역시킨다. 아트에는 소스 가져오기·재연결·팔레트 편집·게임 내 비교를 제공하고 직접 드로잉과 애니메이션 편집은 별도의 제작 도구 이관 과제로 다룬다. | 영역마다 담당자가 Game 뷰에서 생성·검색·편집·시험·저장·복원까지 마친다. 같은 내용을 수정할 수 있는 원본이 두 개 남지 않아야 한다. |
| 6. 팀 작업 검수와 전환 | 최근 작업·즐겨찾기, 클릭한 오브젝트에서 해당 데이터 열기, 브러시 스트로크 단위 실행 취소, 동일 시드 즉시 재시험, 변경 전후 나란히 보기를 다듬는다. 검사가 끝난 옛 도구는 루트 Legacy에 보관하고 실행 경로에서 뺀다. | 레벨 디자이너와 밸런스 담당자가 Inspector나 JSON을 열지 않고 같은 방을 완성한다. 첫 방을 고쳐 시험하기까지 5분을 목표로 관찰하고, 저장 위치·반영 시점·동료 변경 내용을 스스로 설명할 수 있는지 확인한다. |

넓은 이관의 판단 기준은 **처음부터 끝까지 작동하는 작은 제작 경험**이다. 첫 시연은 ‘한 사람이 방의 벽을 칠하고 다른 사람이 같은 방의 전투 웨이브를 고친 뒤, 두 변경을 합쳐 일반 게임에서 플레이하기’로 정한다.
